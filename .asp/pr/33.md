# refactor(tools): ownershipMask 只留一份——check-sprite-sheets 重建版改為匯入 spriteChecks

Closes #33

## 問題

`tools/check-sprite-sheets.mjs:697` 的 `ownershipMaskFor(manifest, cell)` 註解自承
「`spriteChecks` 的 `ownershipMask` 未 export，這裡用同一組規則重建」。

兩份規則的後果不是「程式碼比較醜」，而是**兩條告知路徑會各說各話**：
產權檢查的報表（`checkOverlayOwnership` → `spriteChecks.ownershipMask`）與
給畫師看的那張洋紅 diff 圖（`writeDiffImages` → 重建版）本來就是分別算的。
改一份忘一份，就會變成「報表說格 1 越界，而圖上乾淨」或反過來——
而畫師修圖看的是圖，不是報表。

## 做法

兩個提交，刻意分開，因為 AC-2 要的是**先證明再刪**：

### `19fbf2f` 先證明等價（不刪任何東西）

- `spriteChecks.ownershipMask` 改為 `export`（呼叫點下一個提交才切）
- `check-sprite-sheets.ownershipMaskFor` **暫時** `export`，只為了讓 selftest 拿得到兩份
- selftest 新增 `[3f]` 節：**21 個產權碼 × 8 組刻意刁難的幾何 = 168 組**逐位元比對，
  外加實交付 manifest、合成 manifest、刻意違規產權碼組合的逐格比對

兩者簽名不同（`(code, manifest)` 對 `(manifest, cell)`），所以比的是**合成後的行為**：
把產權碼塞進 `reactionOwnership[0]` 餵給重建版。

### `fb745da` 刪掉重建版、改為匯入

- `ownershipMaskFor` 整支刪掉（34 行），`writeDiffImages` 改呼叫匯入的 `ownershipMask`
- `[3f]` 節由「兩份比對」換成收斂後的永久護欄（見下方〈等價證明去了哪裡〉）
- ~~`tools/asp-test.sh` 的 `MIN_SELFTEST` 156 → 182~~ —— QA 回合已還原（`37fe412`），本 PR **不動** `tools/asp-test.sh`，見〈合併時訂正〉

### 簽名差異怎麼收

重建版多做一件事：`manifest.reactionOwnership[cell] ?? ''`。
`ownershipMask` 是直接 `code.includes(...)`，缺值就是 `TypeError`。
而 diff 的 `cell` 來自**失敗清單**而不是驗證過的 9 格迴圈，所以呼叫點把 `?? ''` 留著——
一個「順便產 diff 圖」的輔助步驟不該把整支工具從 exit 1 變成 exit 2。
行為一字未改，只是防護從函式內搬到呼叫點，並在那裡寫明為什麼不能省。

**沒有選擇「讓 `ownershipMask` 自己容忍缺值」**：那會讓 `checkOverlayOwnership`
（目前缺值即爆）的行為一起變——把缺一格的 manifest 由「爆掉」變成「靜默當空碼」，
而空碼等於「整格都不允許」，九條 SP-7.4 會一起紅得莫名其妙。那是行為變更，不是重複收斂。

### 等價證明去了哪裡

重建版刪掉之後「兩份比對」就無從執行，但證明不能只活在 CI 的歷史裡。`[3f]` 節改成三層：

1. **AC-1 的機械護欄**：`tools/` 底下只有一份實作、`check-sprite-sheets.mjs` 匯入它、
   `spriteChecks` 保持 `export`（沒 export 正是上一次重建的起因）。
   needle 是執行期拼起來的——本檔（連註解）若把那串字原樣寫出來，自己就會變成
   AC-1 那條 grep 的第二筆，讓驗收指令對著一個不存在的重複報警。實際踩過一次。
2. **黃金摘要**：同一組 21 碼 × 8 幾何的遮罩雜湊，**數值是在 `19fbf2f` 用還在的重建版算的**。
   它釘住的不是「現在這份自己算的結果」，而是「收斂後的行為仍等於收斂前的兩份」。
   幾何寫成字面值而不是 `buildManifest()`，摘要才不會隨 fixture 的視窗座標漂。
3. **語意斷言**（餵實交付／合成／違規三組 manifest 的真實九格）：單一視窗碼的遮罩面積
   正好等於該視窗、`K` 不含 E/B/M 任何一個像素（SP-2.12）、加一個字母只放寬不收緊、
   空碼是「全不允許」。黃金摘要擋得住「行為變了」，擋不住「兩份一起錯」——
   尤其空碼弄反成全放行的話 SP-7.4 永不觸發，而那個方向等價證明與摘要都看不出來。

第二列正是留言 1 擔心的事（見下節）：只掃現有 manifest 的九格**證不出等價**。

### AC-3 的「改動前後各跑一次」

- `node tools/check-sprite-sheets.mjs`：前後皆 **exit 0**，stdout 逐字相同，
  `.sprite-check/` 四個產出物（`contact-1-gaze.png` / `contact-2-emotions.png` /
  `contact-3-mouth.gif` / `contact-4-reactions.png`）sha256 全部相同。
- ⚠️ **但實交付素材是 PASS，PASS 就不產 diff 圖**——上面那一輪根本沒走到本次改動的那條路。
  所以另外餵一組刻意越界的合成素材（嘴型畫出 M 窗、覆蓋層畫到斗篷、眨眼吃眉窗、
  BMK 格把不透明線稿畫進眼窗 E），以 `runCheck({spriteDir, outDir})` 逼出 diff 圖，
  在改動前後各跑一次：exit 1 相同、報表的洋紅像素數相同（格 1/2/4/6 → 1/169/1/1）、
  `diff-reactions-1|2|4|6.png` 四個 PNG 的 sha256 **逐一相同**。
- `node tools/check-sprite-sheets.selftest.mjs`：前後皆 exit 0，174 → 182 通過 / 0 失敗。

## 關於 `MIN_TESTS` / `MIN_SELFTEST`

票文〈共同驗收〉把「`tools/asp-test.sh` 的 `MIN_TESTS`（目前寫 189，實際已 258）一併更新」
明文劃進範圍。實際情況與票文快照不同，所以兩個數字分開處理：

- **`MIN_TESTS` 未動，維持 264。** #30（`d52ef58`）已經把它由 189 同步到 264，
  而本票沒有新增 jest 測試（`npm run test:unit` 前後都是 264 passed）。再動就是改錯。
- ~~**`MIN_SELFTEST` 156 → 182。**~~（已由 QA 回合 `37fe412` 還原，現值仍 156。）本票新增的 8 條斷言落在 selftest（jest 的 `testMatch`
  只涵蓋 `src/**`，工具測試寫進 jest 不會被執行——selftest 檔頭就這麼寫），
  所以對應的下限是這一個。數字由 selftest 自己印的「182 通過」抄來，不是手算。

兩者都是**下限**，不同步不會有任何檢查變紅——也就是「加了測試又被整段刪掉」
這件事會無聲通過，正是這兩個常數存在的理由。

## 留言判讀

票上唯一一則留言來自 `asp-ng-supervisor-legacy[bot]`，**非 repo collaborator**，
依 §10 不是 AC 的權威來源。它建議「等價證明須一併涵蓋 selftest 使用的合成 manifest
（含刻意違規的 fixture）」。

**採納，而且加碼**，理由不是它說了，而是它說對了一件可驗證的事：票文 AC-2 只要求
「現有 manifest 的每一格」，而那是**一組樣本**。上面〈等價證明不是恆綠的〉第二列是實測——
拿掉邊界夾取之後，實交付與合成 manifest 的九格**全綠**，只有「視窗被推出格外」
那組刁難幾何抓得到。照 AC-2 的字面做，這個差異會被證明放過。

所以等價證明的覆蓋面是：16 個 EBMK 子集 + 5 個畸形碼（`KMBE` 亂序、`ebmk` 小寫、
`X`、`EEE`、`E B M`）× 8 組幾何（安全框＝整格／安全框小於視窗／視窗被推出格外／
零面積視窗／視窗互相重疊／奇數 `cellPx` 65／極小 `cellPx` 7／實交付比例），
**再加上**留言點名的合成 manifest 與刻意違規的產權碼組合，以及 AC-2 逐字要求的實交付九格。

「刻意違規的 fixture」在這裡只能從 manifest 這一側給：產權遮罩只讀 manifest
（`sheet.cellPx`、`windows`、`margins.silhouetteBox`、`reactionOwnership`），不看像素，
所以把九格換成會讓現有 fixture 紅的產權碼組合（含空碼），才是對這支函式有意義的「違規輸入」。
留言的 triage 建議（tier/milestone）不是 worker 的職權，未處理。
