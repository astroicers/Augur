# fix(core): format.ts 缺值時不再念出 undefined;emotion 的「同一份 normalize」改為可驗證的結構護欄

Closes #39

## 問題

PR #38(#30)合併前的主管層獨立複審留下兩項,本票把它們收掉。

### 1. `format.ts` 把 `undefined` 念出口(QA 在 #38 記錄)

`src/core/format.ts` 的 `formatZh` / `formatEn` 直接把 `a.severity` 塞進模板字串:

```ts
parts.push(`嚴重度 ${a.severity}`)   // severity 缺值 → 「嚴重度 undefined」
```

`ParsedAlert.severity` 標註是 `string`,但告警來自 Grafana 的面板資料,實際可能缺值
(`undefined`)、是 `null`,或根本不是字串。模板字串不會拋例外——它會安靜地把
`undefined` / `null` / `[object Object]` 轉成字串,接著整句被餵進 Web Speech API
**唸出口**。這是 #19 → #30 這條線的第三段:`severity.ts`(#19)與 `emotion.ts`(#30)
都已經改成「不信型別標註,只信 runtime 檢查」,`format.ts` 是同一條髒資料路徑上
最後一個還在信標註的檔。

路徑與 #30 同一條,已實測:`DEFAULT_OPTIONS.minSeverity` 是 `''`(不過濾)
→ `MascotPanel.tsx:747` 的 `meetsMin` 放行缺值告警 → `buildBroadcastPlan`
→ `formatAlert` → 「偵測到告警:HighCPU,嚴重度 undefined,…」。

### 2. 測試名稱宣稱結構,斷言只量到行為

`emotion.test.ts` 的 `正規化規則與 severity.ts 同一份（normalize 是唯一事實源）`,
註解寫「不只斷言結果相同,而是釘住同一套 normalize」,但實際斷言只有:

```ts
expect(severityToEmotion(v, 'firing')).toBe(severityToEmotion(normalize(v), 'firing'))
expect(rankOf(v)).toBe(rankOf(normalize(v)))
```

因為 `normalize` 冪等(`normalize(normalize(v)) === normalize(v)`),`emotion.ts` 內嵌
一份自己的 `trim().toLowerCase()` 副本**也會全綠**。名稱宣稱的是結構,量到的只是行為
——#30 AC-4(重用同一套 normalize)實際上沒有回歸護欄。

## 做法

### `src/core/format.ts`:新增 `speakableSeverity`

```ts
function speakableSeverity(severity: unknown): string {
  const key = normalize(severity)
  return key === null || key === '' ? 'unknown' : key
}
```

- 正規化**重用 `severity.ts` 的 `normalize`**,不在本檔另寫一份(同 `emotion.ts` 的理由:
  「怎麼算同一個嚴重度」只能有一份定義)。
- 非字串 → `normalize` 回 `null` → `'unknown'`;空字串/全空白 → `normalize` 回 `''`
  (**不是** `null`)→ 也走 `'unknown'`。
- 順帶去空白轉小寫,所以 `' CRITICAL '` 念成 `嚴重度 critical` 而不是 `嚴重度  CRITICAL `
  (後者會在句中多出空白)。
- 三處呼叫:`formatZh` 的嚴重度子句、`formatEn` 的嚴重度子句,以及
  `buildBroadcastPlan` 的 `severity` 欄位(見下方 AC-2 (c))。

**為什麼缺值念 `'unknown'` 而不是省略整個嚴重度子句**:缺值 ≡ `unknown` 不是本票自創,
`src/sources/panelAlerts.ts` 的 `labels['severity'] ?? 'unknown'` 早就把「沒有 severity
標籤」收斂成字串 `'unknown'`,`severity.ts` 的 `RANK` 也把 `unknown` 列為排名 0 的已知值。
中文句以「,」串接,省略子句會讓同一支告警的句型隨髒資料飄移(子句數變了),
回放/比對時分不出「沒有嚴重度」與「沒播報」;念 `unknown` 則句型恆定。
這個選擇以斷言釘住(整句比對 + 子句數比對),不是只靠註解。

### `src/core/__tests__/emotion.test.ts`:改名 + 結構護欄(兩邊都做)

票文 AC-1 給的是「改名**或**加結構護欄」的擇一,本票**兩邊都做**:

1. 原測試改名為 `行為一致：正規化前後的 emotion 與 rankOf 同進同出（冪等性，不保證同一份實作）`
   ——如實描述它量的是什麼,並在上方註解寫明冪等性為何讓它量不到結構。斷言一字未改。
2. 另立三條結構護欄,用 `jest.mock` 把 `severity.ts` 包成「委派給真實實作的 `jest.fn`」:
   - `結構護欄：severityToEmotion 把原始值交給 severity.ts 的 normalize（不是內嵌副本）`
     ——斷言 `normalize` 被呼叫、收到的是**未加工的原始值**(`' CRITICAL '` 而非
     `'critical'`,即正規化發生在 `severity.ts` 內)、回傳值正確;非字串走同一條路。
   - `結構護欄：emotion 的判定由 normalize 的回傳值驅動（副本復活會翻紅）`
     ——`mockReturnValueOnce('warning')` 後 `severityToEmotion('critical','firing')`
     必須回 `'warning'`。內嵌副本的實作會忽略這個回傳。
   - `結構護欄：resolved 的早退在 normalize 之前（完全不看 severity）`
     ——斷言 `resolved` 路徑上 `normalize` 一次都沒被呼叫(把 #30 AC-2 的「完全不看
     severity」從同值巧合變成結構斷言)。

**為什麼是 `jest.mock` 而不是票文舉例的 `jest.spyOn`**:本專案的 jest transform 是
`@swc/jest`(`.config/jest.config.js`),swc 的 CJS 輸出把每個 export 寫成
**non-configurable getter**(`Object.defineProperty(exports, name, { get })`),
`jest.spyOn(severityMod, 'normalize')` 會直接拋
`TypeError: Cannot redefine property: normalize`(本票實測過,見〈測試〉)。
`jest.mock` 換掉的是 module registry 的整筆記錄,不受 getter 限制。
包裝一律 `jest.fn(actual.xxx)` 委派真實實作,所以該檔其餘每一條測試斷言的都還是真邏輯。

#### 護欄有效性:實測「副本復活」會翻紅

把 `emotion.ts` 的 `import { normalize }` 換成檔內自備的
`const normalize = (v: unknown) => typeof v === 'string' ? v.trim().toLowerCase() : null`
(行為一字不差的副本),跑 `emotion.test.ts`:

| 測試 | 副本復活後 |
| --- | --- |
| 原本那條(改名前後斷言相同) | ✓ 綠 ← **這就是本票要修的洞** |
| `結構護欄：…交給 severity.ts 的 normalize` | ✕ **紅** |
| `結構護欄：emotion 的判定由 normalize 的回傳值驅動` | ✕ **紅** |
| 其餘 8 條行為測試 | ✓ 綠(副本行為相同,本該綠) |

`Tests: 2 failed, 9 passed`。改動已還原(`git diff src/core/emotion.ts` 零輸出),
**本票未改 `emotion.ts`**。
