## 問題

播報紀錄（ADR-006）的名字取自 annotation 自由文字 `RuleName {labels} - values` 的規則名
（`historyToEntries` 裡的 `a.alertName ?? parsed?.title`）。#69 之後播報端已經能改讀
`wall_alertname` 這類 instance label，紀錄端卻沒有 —— 於是同一則告警在兩邊**叫不同名字**：

1. EKS 總規則（eks-infra#1210）底下所有告警的紀錄仍顯示同一個規則名，名字沒有資訊量
   （而資料其實拿得到：`{labels}` 段裡就有 `wall_alertname`）。
2. 名字進句子，而句子正是 `MascotPanel` 判斷「這一則紀錄裡已經有了嗎」的依據
   （`e.text === l.plan.text && |e.time - l.at| <= SESSION_MATCH_WINDOW_MS`）。
   兩邊不同名 → 句子不同 → 合併判不中 → **同一則告警在清單上列兩次**。

## 做法

一個選填欄位 + 一個純函式 + 一行接線。**沒有新模組、沒有新選項、沒有改請求。**

| 新增／改動 | 做什麼 |
| --- | --- |
| `historyToEntries(raw, templates, opts)` 的 `opts.alertNameLabel?: string` | 選填；不給／留空／只有空白 = 照舊 |
| `historyAlertNameOf(labels, ruleName, nameLabel)`（`sources/history.ts`，新，module-private） | 取一筆紀錄念出來的名字，**唯一一處**。播報端的對應物是 `panelAlerts.ts` 的 `alertNameOf` |
| `historyToEntries` 裡 `name` 拆成 `ruleName` 與 `name` | `ruleName` 查樣板（AC-4），`name` 進句子、`fingerprint` 與 `key` |
| `MascotPanel.tsx` 的紀錄 effect | 把既有的 `alertNameLabel`（#69 已在第 329 行算好）帶進 `historyToEntries` |
| `docs/ARCHITECTURE.md`、`src/README.md` | 文件同步 |

`historyFetcher.ts` **一行未改**：三個端點的請求與回應都不含名字的決定，取名完全在轉換層。

### 關鍵：念名與規則身分分離（AC-4）

```ts
const ruleName = a.alertName ?? parsed?.title ?? 'unknown';
const tpl = templates.get(ruleName);                          // ← 永遠用規則名
const name = historyAlertNameOf(parsed?.labels, ruleName, nameLabel);  // ← 念出來的名字
```

`templates` 的鍵是 Grafana 的規則名（`parseRuleTemplates` 與 `parseRulerConditions` 都用
`rule.name`／`grafana_alert.title`）。拿 label 值去查會**整組查不到**，症狀是摘要、條件欄的
數值、規則層嚴重度三樣一起消失 —— 而句子照樣組得出來，所以那是**靜默**失效。
兩支測試從正反兩面釘住它：查得到（鍵是規則名時三樣都在）、查不到（鍵換成 label 值時填不進去）。

### 取捨一：`alertNameLabel` 刻意**不**進紀錄 effect 的相依陣列

紀錄 effect 原本的 deps 是 `[data, id, minSeverity, alertLang, severityAliasSpec]`，而
`severityAliasSpec` 也是文字選項 —— 照那個先例，新選項「應該」一起放進去。這裡沒有這麼做，
加了 `eslint-disable-next-line react-hooks/exhaustive-deps` 與一段註解，理由是 **AC-5**：

放進 deps 的話，在編輯面板改這一欄會讓紀錄**立刻**換名，而本分頁已念過的那些句子還是舊名
（導播 effect 刻意不含這個選項，#69 的取捨）。下一輪 refresh 之前，兩邊名字不一致 ——
那正是 AC-5 要擋的「同一則列兩次」。不放進去，兩邊都只在 `data` 刷新時讀同一個選項值，
換名同進同退。代價是改了這一欄要等下一輪 refresh 生效，而那正是 #69 已經寫進 `src/README.md`
與編輯器說明的那句話（"takes effect on the panel's next refresh"），不是本票新增的語意。

`eslint-disable` 不是為了消警告而加的：拿掉它 `npx eslint` 會紅在
`missing dependency: 'alertNameLabel'`（已實跑確認），所以它確實擋著一個真的規則，
而不是一個失效的 suppress。

### 取捨二：`fingerprint` 與 `key` 也用念出來的名字

紀錄**永不進 dedup**（ADR-006 決策 5），所以這兩個欄位在生產路徑上不影響去重；
改它們是為了與 #69 的「名字就是去重單位」保持同一個語意，讓同一則告警在兩邊的
`ParsedAlert` 逐欄對得上（AC-2 的句子比對就是拿一則手寫的 `ParsedAlert` 餵
`buildBroadcastPlan` 去比的）。`key` 實際上幾乎都走 `a.id`，名字只在沒有 id 時才進去。

### 取捨三：`{labels}` 的解析代價明文化（回應票上留言）

見下方〈票上留言的判讀〉。沒有改 `parseAnnotationText`，而是補三個 fixture 把三種
label 值的**實際行為**釘住，並在 `history.ts` 與 `docs/ARCHITECTURE.md` 寫明。

## 票上留言的判讀

留言來自 `asp-ng-supervisor-legacy[bot]`（**非 repo collaborator**，依簡報僅供參考、不是 AC 的
權威來源）。它的 AC 補強建議**採納**，並且照它給的兩個選項**兩個都做**：

> label 值若含 `,`、`=` 或空白（Grafana 的 label 值允許這些字元），粗略解析會靜默取到錯的值，
> 而這條路徑的產物會被念出來。建議補一條：明文宣告只支援現有 fixture 形狀並在取不到時退回
> 規則名（AC-3 的路徑），或補一個含 `,`/`=`/空白 label 值的 fixture 釘住行為。

先實測，不推理。`parseAnnotationText` 的拆法是 `body.split(/, (?=[A-Za-z_][A-Za-z0-9_]*=)/)`
再逐段 `^(名稱)=(.*)$`，於是三種值的行為**不一樣**，籠統說一句「含這三種字元會拆錯」是錯的：

| label 值 | 實際行為 | 釘住它的測試 |
| --- | --- | --- |
| 含空白（`Kubelet Too Many Pods`）、含 `=`（`a=b=c`） | **完整取到**（`(.*)` 吃到該段結尾） | 「值裡有空白或 `=`：完整取到」 |
| 含 `, ` 但後面不是 `<label 名>=`（`a, b`） | **不受影響**，整段都是值 | 「值裡有 `,` 但後面不是 `<label 名>=`：不受影響」 |
| 含 `, <合法 label 名>=`（`x, y=1`） | **拆錯**：取到 `x`，`y=1` 被當成另一個 label | 「值裡有 `, <合法 label 名>=`：已知會拆錯，名字被截斷到那裡為止」 |

第三種是唯一真的壞掉的情形，而且**不會**走 AC-3 的退路（取到的值非空），所以失敗形態是
**念錯名字**（截斷），不是空名、也不是例外。這個代價來自 annotation 文字格式本身沒有文件保證
（ADR-006〈接受的代價〉），本票不改那支解析器 —— 改它需要一個能分辨「值裡的逗號」與
「分隔用的逗號」的規則，而那個規則同樣沒有依據可寫，只會把猜測搬到另一個地方。
於是按留言的第一個選項**明文宣告**：`historyAlertNameOf` 與 `parseAnnotationText` 的 docstring
各寫明受影響面與不受影響面，`docs/ARCHITECTURE.md` 也寫了一句；並按第二個選項**補 fixture**，
三種值各一條，行為不靠讀程式推。

triage 建議（tier:2、milestone P9、不標 dedup_of）不是本票的交付物，未處置。
