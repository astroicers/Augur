# fix(core): severityToEmotion 缺值或非字串的嚴重度不再拋例外

Closes #30

## 問題

`src/core/emotion.ts` 的 `severityToEmotion(severity: string, status)` 直接呼叫
`severity.trim().toLowerCase()`。型別標成 `string`,但告警來自 Grafana 的面板資料,
實際可能缺這個欄位(`undefined`)、是 `null`,或不是字串——此時拋 `TypeError`,
表情更新跟著中斷。

這是 #19(PR #22)修掉 `severity.ts` 同類缺陷時留下的殘留:`.asp/pr/19.md`〈殘留〉
已實測記下完整路徑——`DEFAULT_OPTIONS.minSeverity` 是 `''`(`src/panelOptions.ts`,
空字串=不過濾)→ `MascotPanel.tsx` 的 `meetsMin` 放行缺值告警 → `buildBroadcastPlan`
(`src/core/format.ts:23`)→ `severityToEmotion(undefined, 'firing')` → 爆。
本票把這條路徑的最後一段補上。

## 做法

- `src/core/severity.ts`:把原本私有的 `normalize(severity: unknown)` 改為 **export**。
  邏輯一字未改(`typeof === 'string'` 才 `trim().toLowerCase()`,否則回 `null`),
  只動可見性 + doc comment 說明「為何要匯出」。
- `src/core/emotion.ts`:入參由 `severity: string` 放寬成 `severity: unknown`,
  `severity.trim().toLowerCase()` 換成 `normalize(severity)`。非字串 → `null` → 落 `default`
  → `calm`,與 `unknown` 同。`status === 'resolved'` 的早退在 normalize 之前,
  所以 resolved 完全不看 severity(AC-2)。

AC-4 要的是「重用同一套正規化規則」,所以選匯出 `severity.ts` 的 `normalize`,
而不是新開一個 `core/normalize.ts`:後者會動到 `severity.ts` 既有的 import 面,
而本票範圍只給「必要時 `severity.ts` 的匯出」。「怎麼算同一個嚴重度」只能有一份定義,
否則排名與表情會各自漂移(例如一邊 trim 一邊不 trim),同一筆告警出現
「排名達標但表情不對」的不一致。

### 行為差異範圍

先前**能跑**的輸入(字串)結果一字未改——`normalize` 對字串做的就是原本那兩個呼叫。
`'constructor'`/`'__proto__'` 這類原型鍵在 `emotion.ts` 本來就沒問題(用的是 `switch`
而非物件查表,#19 踩到的是 `RANK` 物件字面值),測試裡釘它們是回歸護欄,不是修掉的缺陷。
先前**不能跑**的輸入(非字串)舊行為是拋例外,無可回歸的語義。

## 環境限制:gitleaks 在 worker 容器缺席(與 #19 同一件,非本票 diff 所致)

`ASP_GATE_MARKERS=1 bash .asp/gate.sh` 在本票 HEAD 的輸出:

```
asp:gate-check id=gitleaks sev=blocker rc=1 status=missing
asp:gate-check id=commit-format sev=blocker rc=0 status=ok
```

實測:`command -v gitleaks` 無、`~/.asp/tools/` 不存在、容器無對外網路,
故 worker 無自補路徑(完整診斷見 `.asp/pr/19.md` 同名小節,此處不重複)。

退出碼依模式分岔(本票 HEAD 實測):

| 模式 | 結論行 | exit |
| --- | --- | --- |
| 預設 | `gate 通過但不完整(warnings=0)` | **0** |
| `ASP_GATE_STRICT=1`(fail-closed,代發前的合理設定) | `gate 未完整執行(warnings=0)——未執行者之中有已宣告 requires 的 blocker,不放行` | **202** |

成因讀得出來:`asp-gate.yaml` 的 `requires` 只列 `.asp/gitleaks.toml`(規則庫,存在),
**沒有列 `cmd:gitleaks`**。於是 `require_inputs` 過關(規則庫在),缺的是執行檔,
走到 `run_check` 的缺工具分支 `_unrun_blocker "$id" "工具未安裝:$req" "$STRICT"`——
翻不翻紅取決於 `STRICT`,不取決於宣告。預設模式那句「未執行者皆未宣告 requires」
因此在這一支上字面不準(它宣告了,只是宣告的是規則庫而非工具),
但**兩種模式都把本輪記成「gitleaks 什麼都沒保證」,逐支標記也都是 `rc=1`**——
代發側若採 fail-closed 就會是紅,且**與本票 diff 無關**。
處置建議同 #19:在 worker base image 落地 gitleaks vendoring,
或在 `asp-gate.yaml` 的 `requires` 補 `cmd:gitleaks` 讓「沒跑」在預設模式也說得清楚。
兩者都屬 asp-ng / base image 側,不在本票範圍。

**不會做的兩件事**(同 #19):不改 `asp-gate.yaml` 把 gitleaks 降級或加豁免
(那是為了自己過關而削弱密鑰閘,且該檔是 asp-ng 側的單一事實源);
不手寫 `.asp-test-result.json` 偽造綠痕跡。

替代證據(gitleaks 缺席期間):本票改動的 5 個檔案逐一套用通用憑證樣式
(雲端存取金鑰、VCS/聊天平台 token、私鑰 PEM 標頭、JWT、`key`/`secret`/`password` 賦值)
以及 `.asp/gitleaks.toml` 的附加規則,**零命中**——本票 diff 只有型別放寬、
一個 `export` 關鍵字、測試斷言與一個整數常數,不含任何字串字面值形式的憑證。
界限同 #19:grep 無法重現 gitleaks `useDefault = true` 的熵值型規則全集。
