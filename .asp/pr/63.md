# feat(director): 靜音／值班時段——排程內照常更新畫面但不念（quietHours）

Closes #63

## 問題

值班室與牆面螢幕需要「夜間不出聲、但畫面照常更新」。現在唯一的靜音是 ADR-007 那顆
**每個瀏覽器各自**的鈕（存 `localStorage`，按的人是觀看者），沒有辦法在 dashboard 上
設定「每天 22:00 到 07:00 不念」。

導播（`src/director/BroadcastDirector.ts`，#58）已經有一條「靜音時照樣回 `items`、
只是不交付」的路徑。本票把**排程靜音**接到**同一條**路徑上，而不是新增一層。

## 做法

兩個新 panel 選項 + 導播裡的一道交付閘門 + 四個純函式。

| 新增 | 做什麼 |
| --- | --- |
| `quietHours`（文字，預設 `''`） | `HH:MM-HH:MM` 的靜音時段。空字串 = 沒有排程靜音 |
| `quietAllowCritical`（布林，預設 `false`） | 時段內仍念 `critical` 的 firing |
| `parseQuietHours(spec)` | 設定字串 → `{ range, problem }`。不拋例外 |
| `isQuietAt(range, minuteOfDay)` | **起點含、終點不含**；跨午夜走「或」 |
| `minuteOfDayAt(epochMs)` | 時刻 → 當天的第幾分鐘（**瀏覽器本地時間**） |
| `describeQuietHours(problem)` | 解析失敗的原因講成一句話（AC-4 的「回報原因」） |

交付閘門在 `evaluate()` 的最後一段，順序是刻意的：

```
過濾（門檻＋別名）→ 防洪（dedup）→ 組句 → items
  → 沒有播報器？ 不交付
  → 每瀏覽器靜音（ADR-007）？ 不交付        ← 先判這個
  → 排程靜音時段內？ 只放 breaksQuiet() 過（quietAllowCritical 且 critical firing）
  → 其餘照時間順序交給播報器
```

- **在 dedup 之後**：時段內的告警照樣被 dedup 記成「播過」，所以時段結束時不會一口氣
  補念出來（AC-2 第三點）。移到門檻那一段去過濾的話，被吞掉的告警不但沒進 dedup，
  等它恢復時還會冒出一句「已恢復」—— 與「被門檻擋下的告警不得進 dedup」同一個坑的反面。
- **每瀏覽器靜音先判**：`quietAllowCritical` 於是在結構上不可能蓋過觀看者自己按下的開關。
- **一輪只讀一次時鐘**：同一輪的每一則吃同一個時段判斷（第 4 條不變量「一輪是原子的」的延伸）。

嚴重度判斷走 `resolveSeverity(…, aliases) + meetsMin(…, 'critical')`，`aliases` 就是
門檻那一行用的**同一份**解析結果（#51）；`critical` 是排名最高的一級，所以
`meetsMin(…, 'critical')` 等於「它是 critical」。兩邊各自比字串遲早會漂成
「門檻放它過卻破不了靜音」。

元件這一側是**純接線**（AC-5）：`options.quietHours ?? ''` 與
`options.quietAllowCritical ?? false` 原樣帶進 `DirectorSettings`，
`MascotPanel.tsx` 沒有任何時段判斷：`grep -n 'isQuietAt\|parseQuietHours\|getHours' src/components/MascotPanel.tsx` 只有**一個命中，而且是註解**（那行指路給導播的兩個純函式），程式碼零命中。

### 取捨一：純函式住在 `BroadcastDirector.ts`，沒有開 `src/core/quietHours.ts`

票文的〈範圍〉允許「`src/core/` 下新的純模組（**若需要**）」，本票沒有開。理由是機械的：
#58 留下的既有測試 `AC-1：導播不 import react、不碰 DOM` **逐項比對導播的 import 清單**
（`expect(sources).toEqual([...六項...])`），所以多一個 `import … from '../core/quietHours'`
就會讓那支既有測試變紅，而本票 AC-1 要的正是「既有測試一行不改且全綠」。

兩者兼得只有兩條路：拆檔並改那支測試一行（違反 AC-1），或把純函式放進導播（不動既有測試）。
選了後者，而且這幾個函式唯一的呼叫端就是導播的交付閘門。檔內那一段註解把這個理由寫下來了，
**日後要拆成 `core/` 模組的改動就是那一行 import 清單** —— 如果主管層偏好拆檔，
那是一行測試 + 一次 `git mv` 的事，請在 QA 回合說一聲。

### 取捨二：`critical` 的 **resolved 不破靜音**

AC-3 的字面是「`critical` 的 **firing**…其餘照 AC-2 處理」，實作照字面做，並補上理由：
半夜破靜音的意義是「有事需要有人起來處理」，恢復不需要。代價誠實記下來 ——
破過靜音的那則 critical 在時段內恢復時不會有人聽到，要到早上看清單（清單在時段內照常更新）。
這與「播過 firing 就該播恢復」那條**刻意相反**，而那條守的是嚴重度門檻（調高門檻不該讓恢復消失），
不是這條。若主管層認為恢復也該破靜音，改動是 `breaksQuiet()` 裡的一個 `status` 判斷
加一支測試的反向斷言。

### 取捨三：端點規則**定下來**，不留「例如」

**起點含、終點不含**（`[startMin, endMin)`）。`22:00-07:00` 在 22:00 整靜音、07:00 整
恢復出聲，所以相鄰的兩段接得起來而不重疊。釘它的不只兩條邊界斷言，還有一條通則測試：
`07:00-12:00`／`12:00-22:00`／`22:00-07:00` 三段對一天的 1440 分鐘**每一分鐘都剛好命中一段**。

### 取捨四：相依陣列不含這兩個選項

導播 effect 的 deps 維持 `[data, id, minSeverity, alertLang, severityAliasSpec, directorFor]`，
新的兩個選項與 `repeatFiringMin`／`fallbackSeverity` 同一條理由（既有的 `eslint-disable` 註解
已更新成「這四個」）：它們只在 effect 真的跑時才被讀，那一刻讀的是最新一輪 render 的閉包；
放進 deps 只會讓「在編輯面板裡改它們」各多打一次 rules 端點。代價是改了要等下一輪 refresh
才生效 —— 而時段邊界本來就只在 refresh 當下被看一眼（時段結束不補念，所以沒有「錯過一輪」這回事）。

### 全形：**接受**

`２２：００－０７：００` 與 `22：00－07：00` 都認得（全形 ASCII U+FF01–U+FF5E 整段偏移
0xFEE0，所以全形數字一併認得；全形空白換成半形）。理由與 `core/severityAliases.ts` 收全形
分隔符同一條：編輯器說明是中文，中文輸入法打出來的冒號就是 `：`。只認半形的話整個選項會
**靜默失效**，而使用者看不出哪裡錯。`~`、空白、頓號**不是**分隔符（只收 `-` 與全形 `－`）。

## 票上留言的判讀

留言 1（`asp-ng-supervisor-legacy[bot]`，**非** repo collaborator）依 §10 只供參考、不是 AC

- **(a) 本地時間 vs「所有觀看者共用」**：票文 AC-2 已寫「以注入的時鐘、瀏覽器本地時間判斷」，

## 合併時訂正（2026-10-15，asp-ng 主管層）

獨立複審逐行對過 main：**實作沒有錯**，留空時每條路徑都相同，#58 的五條不變量也都沒被弄壞。卡住的是測試有沒有真的驗到它說的事：

- **MED（本地時間驗不到）**：`jest.config.js` 把 TZ 固定成 UTC，在 UTC 下 `getHours()` 與 `getUTCHours()` 恆等。實作若誤用 UTC 鐘點，原有測試全都會照綠；上線後 UTC+8 的螢幕會在本地 06:00–15:00 靜音。主管層新增測試 `AC-2：minuteOfDayAt 讀本地鐘點（getHours／getMinutes），不是 UTC 鐘點`：讓本地鐘點與 UTC 鐘點回不同的值，斷言結果跟著本地那一組走。**變異實測**：把實作改成 `getUTCHours()`／`getUTCMinutes()`，這一條會紅；換回原實作則全綠。（先試過在測試中途改 `process.env.TZ`，在 jest 的測試環境裡不生效，所以改用這個做法。）
- **MED**：GitHub 上的 PR 本文已用本檔同步（測試數為最終 head 的實數）。
- **LOW（名稱說得比斷言多）**：兩支「與沒有這個選項時完全相同」只驗了交付幾句，改名為「照常交付／照常念出」。留空時與 main 相同，靠的是複審逐行比對，加上既有測試一行未改且全綠。「吃同一份別名解析結果」驗不到「同一份」，改名為「會套別名」；「同一份」由程式碼（同一個 `aliases` 區域變數）保證。
- **接受為已知取捨**：時段內，critical 只破靜音念 firing；它的恢復句照票文「critical 的 firing」的字面處理，會被 dedup 收下而不念。半夜破過靜音的 critical，恢復時不會被聽到。這一條已在上方〈取捨二〉揭露。要改就另開票。
