# fix(core): format.ts 的 name / instance / summary / value 缺值或非字串時不再念出 undefined / [object Object]

Closes #46

## 問題

PR #45（#39）把 `format.ts` 的 **severity** 收乾淨了，但同一個檔的其他欄位還在信型別標註。
`.asp/pr/39.md`〈殘留〉第 1 條已經明文揭露，本票把它收掉。

`formatZh` / `formatEn` 原本是這樣組句的：

```ts
parts.push(`偵測到告警：${a.name}`)                              // name 缺值 → 「偵測到告警：undefined」
if (a.instance) {parts.push(`受影響對象 ${a.instance}`)}        // {} 是 truthy → 「受影響對象 [object Object]」
if (a.value !== undefined) {parts.push(`目前數值 ${formatNumber(a.value)}`)}
if (a.summary) {parts.push(a.summary)}                          // 同 instance
```

三種不同的守門，三種不同的洞：

| 欄位 | 既有守門 | 擋得住 | 擋不住（實測唸出口的字串） |
| --- | --- | --- | --- |
| `name` | 無 | — | `undefined`、`null`、`[object Object]`、`1,2`、`true`、`() => 'x'` 的原始碼 |
| `instance` / `summary` | `if (a.x)`（truthiness） | `undefined` / `null` / `''` | `{}` → `[object Object]`、`[1, 2]` → `1,2`、`42` → `42`、`true` → `true` |
| `value` | `!== undefined` + `formatNumber` 第一行 `if (!Number.isFinite(n)) return String(n)` | `undefined` | `{}` → `[object Object]`、`[1, 2]` → `1,2`、`null` → `null`、`NaN` → `NaN`、`Infinity` → `Infinity` |

`value` 那一格特別值得記：守門**存在**，但它的行為（`String(n)`）正好產出本票要擋的東西。
`Number.isFinite({})` 是 `false`、`String({})` 是 `'[object Object]'`——這是「有檢查所以安全」的反例。

四個欄位與 severity 走的是同一條髒資料路徑：Grafana 面板資料 → `panelAlerts.ts`
→ `buildBroadcastPlan` → `formatAlert` → Web Speech API **唸出口**。模板字串不會拋例外，
它會安靜地把垃圾轉成字串。這是 #19（`severity.ts`）→ #30（`emotion.ts`）→ #39（`format.ts` 的 severity）
→ #46（`format.ts` 的其餘欄位）這條線的第四段。

另外 `src/core/types.ts` 的 `BroadcastPlan.severity` 註解仍寫「原始嚴重度」，
但 #39 之後實作已經是 `speakableSeverity(a.severity)`（正規化後的值）——註解在說謊。

## 做法

### `src/core/format.ts`

新增兩個守門函式，與 #39 的 `speakableSeverity` 並列、同一套命名與同一條理由
（「不信型別標註，只信 runtime 檢查」）：

```ts
/** name / instance / summary */
function speakableText(v: unknown): string | undefined {
  return typeof v === 'string' && v.trim() !== '' ? v : undefined
}

/** value */
function speakableNumber(v: unknown): string | undefined {
  return typeof v === 'number' && Number.isFinite(v) ? formatNumber(v) : undefined
}
```

以及替代詞常數（AC-1 要求「改念的替代詞要寫明」——值就定在程式碼裡，不是散在測試裡）：

```ts
const UNNAMED_ZH = '未命名告警'
const UNNAMED_EN = 'unnamed alert'
```

組句端：

```ts
const name = speakableText(a.name) ?? UNNAMED_ZH   // en 側是 UNNAMED_EN
const instance = speakableText(a.instance)
const value = speakableNumber(a.value)
const summary = speakableText(a.summary)
...
if (instance !== undefined) {parts.push(`受影響對象 ${instance}`)}
if (value !== undefined) {parts.push(`目前數值 ${value}`)}
if (summary !== undefined) {parts.push(summary)}
```

`formatNumber` 第一行的 `if (!Number.isFinite(n)) {return String(n)}` **移除**：
守門上移到 `speakableNumber` 之後它既是死碼（唯一呼叫端已保證 `n` 是有限 `number`），
又會誤導下一個讀者以為非有限值有被處理——而它「處理」的方式正是回傳 `'[object Object]'`。
函式的 doc comment 補上前置條件。

#### 三個語義決策，逐一記明

1. **`name` 缺值「照樣唸、只是唸替代詞」，不省略整個子句。**
   理由與 #39 的 `speakableSeverity` 同一條：名稱是句子的主語，省掉會讓句子塌成
   「偵測到告警：，嚴重度 critical。」——那是另一個句型，回放／比對時分不出
   「告警沒有名字」與「句子組壞了」。
2. **替代詞不沿用 severity 的 `unknown` / 「未知」。**
   「未知告警」會被聽成「這則告警的內容不明」，但這裡不明的只有名稱，其餘欄位照常唸得出來。
   選 zh `未命名告警` / en `unnamed alert`。#39 的〈殘留〉說「`name` 的缺值該念什麼沒有既有慣例可依」——
   本票就是那張票，所以這裡**是**有票據的裁定，不是順手決定。
3. **`instance` / `summary` / `value` 回 `undefined` 讓整個子句消失，不給代表字。**
   這三個本來就是 `ParsedAlert` 的可選欄位，「省略整個子句」正是它們缺值時的既有行為；
   髒值收斂到缺值，輸出就與缺值完全一致（本票有一條測試直接釘住這個等價）。

### `src/core/types.ts`（AC-4）

`BroadcastPlan.severity` 的註解從「原始嚴重度（critical/error/warning/info/unknown）」
改成據實描述 #39 之後的實作：去空白、轉小寫，缺值／空白／非字串收斂成 `'unknown'`，
與 `text` 裡唸出的那個嚴重度保證同值，**不是** `ParsedAlert.severity` 的原值。

順帶把 `BroadcastPlan.name` 的註解也改成據實：它**仍是原樣轉手**，缺值時這個欄位就是
`undefined`／非字串，與 `text` 裡唸出的替代詞不保證一致（理由見〈殘留〉第 1 條）。
不寫這一行的話，AC-4 修掉一個說謊的註解、卻留下另一個會被誤讀為「已經收斂」的註解。

## 殘留（本票刻意不修，明文留痕）

1. **`BroadcastPlan.name` / `.instance` / `.value` 這三個欄位仍原樣轉手。**
   本票修的是「唸出來的句子」——票文標題寫的是「**念出** undefined / [object Object]」，
   AC-1/AC-2 的 Then 也都是「句子裡不會出現」。`plan.name` 不會被唸，但它會被
   `MascotPanel.tsx:663/872/875` 當成**補念去重的 map key**，缺值時那個 key 就是 `undefined`。
   實際影響有限（所有缺名稱的告警本來就共用 `undefined` 這一個 key，改成共用替代詞字串
   並不改變碰撞行為），但「欄位與 text 不一致」確實是 #39 為 severity 修掉、而這裡還在的事。
   不順手做的理由：那是 `BroadcastPlan` 的**契約變更**，會動到下游消費端，
   與「讓句子乾淨」是兩個決策；本票已在 `types.ts` 的註解把這個不一致寫明，
   下一個改它的人至少不會以為已經收斂。建議另開一票。
2. **`ParsedAlert` 的型別標註仍在說謊**（`name: string`、`instance?: string`、`value?: number`
   實際可能是任何東西）。runtime 已收斂，型別層沒有。同 `.asp/pr/39.md`〈殘留〉第 2 條，
   根治要改來源層的契約，不在本票範圍。
3. **`summary` 的內容本身沒有任何清洗。** 它是使用者在 Grafana 規則裡寫的自由文字，
   可能含 `[no value]`（`history.ts` 的 `NO_VALUE`）這種 Grafana 自己的佔位字串。
   那不是 JS 轉字串痕跡、也不在票文範圍，本票只保證它是個非空字串。
