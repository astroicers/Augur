# feat(core): 選項 speakValue——可關掉「目前數值」子句（ALERTS 恆為 1）

Closes #71

## 問題

播報句只要有可念的數值就會加上「目前數值 N」（`src/core/format.ts`，中英兩套）。
EKS 的總規則（eks-infra#1210）查的是 `ALERTS`，值恆為 1，於是每一則都念
「目前數值 1」——沒有資訊量，還把播報拖長。其他「條件只是 0／1」的規則同病。

## 做法

一個新 panel 選項 + 組句入口多收一個選填參數 + 兩條呼叫路徑原樣轉手。

| 新增 | 做什麼 |
| --- | --- |
| `speakValue`（布林，預設 `true`） | 播報句與播報紀錄要不要帶「目前數值 N」子句 |
| `FormatOptions`（`src/core/format.ts` 匯出） | 組句開關的物件型別；目前只有 `speakValue?: boolean` |
| `spokenValue(v, opts)`（檔內私有） | 中英兩套**共用**的那一道判斷：`opts?.speakValue === false` → `undefined`，否則照 `speakableNumber` |

組句入口的簽章變成：

```
formatAlert(a, lang?, opts?)
buildBroadcastPlan(a, lang?, aliases?, opts?)   ← opts 原樣轉給 formatAlert
```

接線只有兩處，都是 `buildBroadcastPlan` 的既有呼叫端：

```
MascotPanel.tsx  options.speakValue ?? true
  ├─ 導播 effect → DirectorSettings.speakValue → BroadcastDirector.ts:504 buildBroadcastPlan(…, { speakValue })
  └─ 紀錄 effect → historyToEntries(…, { speakValue }) → history.ts:254 buildBroadcastPlan(…, { speakValue })
```

### 判斷放在組句層、中英共用一份（AC-2／AC-3 的機械保證）

`spokenValue` 是中文與英文兩套唯一的數值來源。若改成在各自的
`if (value !== undefined)` 旁邊再加條件，就會出現「中文不念、英文照念」這種
只改一半的失敗形態——而那正是 AC-2「其餘子句逐字相同」最容易漏掉的縫。
變異測試驗過這條（見下方 M2：只讓中文套用開關 → 5 支紅）。

紀錄（ADR-006）照 AC-3 **不另寫一套**：它與播報吃同一個 `buildBroadcastPlan`，
選項原樣轉手，所以「紀錄句與播報句逐字相同」（G-ADR006-2）在關掉之後仍然成立，
並由一支測試直接以播報管線的輸出當期望值釘住。

### 取捨一：`opts` 收**物件**而不是第四個布林位置參數

`buildBroadcastPlan` 已有 `lang`／`aliases` 兩個位置參數，再疊一個布林會寫成
`buildBroadcastPlan(alert, lang, aliases, false)`——呼叫端讀不出那個 `false` 是什麼。
「哪些子句要念」這一族旋鈕預期會再長，所以收成 `FormatOptions`，呼叫端是
`{ speakValue }`，自帶名字。整個物件省略／空物件／`{ speakValue: undefined }`
三者都與先前完全相同（測試釘住三種寫法）。

### 取捨二：`false` 才關，`undefined` 與 `true` 同義

判斷寫成 `opts?.speakValue === false`，不是 `!opts?.speakValue`。舊 dashboard 存下來的
panel JSON 沒有這個鍵，讀到 `undefined`；寫成否定式會讓**所有既有 dashboard 立刻
不念數值**，正面違反 AC-1。這個方向由變異測試驗過（M1：改成 `!opts?.speakValue`
→ 31 支紅，其中多數是 #39／#46 既有的整句斷言）。

同一條理由讓三個型別都宣告成選填：`MascotPanelOptions.speakValue?`、
`DirectorSettings.speakValue?`、`historyToEntries` 的 `opts.speakValue?`——既有的字面值
（含測試 fixture）一行都不必補，而 AC-1 要的正是「既有測試不改」。

### 取捨三：選項**不**加 `showIf: (c) => c.enableTTS`

同檔其他語音相關選項都藏在「開啟語音」之下，這一個刻意不藏：關掉語音後播報紀錄
（ADR-006）照樣顯示句子，而這個開關對那些句子一樣生效。藏起來會讓使用者以為
「反正沒開語音，撥它沒差」。有一支測試釘住 `showIf` 是 `undefined`。

### 取捨四：`BroadcastPlan.value` 欄位**不**受影響

關掉只少念那一段，`plan.value` 照舊在有值時帶上。那一欄的註解寫明是「供前端
feed／除錯」的**原值**，與唸出來的字分開記（同 `plan.severity` 與唸出的嚴重度
分開記的理由）。下游若哪天要顯示數字，不該因為「不念」而拿不到資料。
測試釘住：關掉時 `plan.value === 95.2`，且除 `text` 外每個欄位與開著時逐值相同。

### 取捨五：`speakValue` **放進**兩個 effect 的相依陣列

導播 effect 的 deps 原本刻意不含 `repeatFiringMin`／`fallbackSeverity`／`quietHours`／
`quietAllowCritical`（省掉在編輯面板裡改它們時多打的 rules 端點）。`speakValue` 走
`alertLang` 那一類：它改的是**句子本身**，在編輯面板裡撥了之後要能立刻看到新句子
（紀錄那一側同理，否則撥完之後清單上的句子要等下一次 refresh 才跟上）。
代價是撥動它會多打一次 rules／history 端點，與改語言的代價相同。

## 票上留言的判讀

留言 1（`asp-ng-supervisor-legacy[bot]`，**非** repo collaborator）依 §10 只供參考、
不是 AC 的權威來源，本票照**票文**做。它的兩點 AC 建議如下判讀：

- **(a)「紀錄端是另一個 `buildBroadcastPlan` 呼叫點，應明文列進範圍」**：票文〈範圍〉
  已含「傳選項的最小接線」，而 AC-3 明文要求紀錄也不含數值子句——兩句合起來，
  改到紀錄那一側的檔就是票文要求的接線，不是越界。本票照這個讀法做，動到的紀錄側
  只有兩行（`historyToEntries` 的 `opts` 型別多一欄、`buildBroadcastPlan` 多傳一個參數）
  加註解，沒有碰紀錄的任何其他邏輯。
  留言對呼叫點位置的描述**與本工作卷的實際狀態不符**：本副本的
  `grep -rn buildBroadcastPlan src --include=*.ts --include=*.tsx` 只有兩個呼叫端，
  `src/director/BroadcastDirector.ts` 與 `src/sources/history.ts`；`MascotPanel.tsx`
  **沒有**呼叫 `buildBroadcastPlan`（它第 952 行附近的試聽句是手寫的 `BroadcastPlan`
  字面值，本來就沒有數值子句，不受本票影響）。
- **(b)「與 #69 都要更新文件裡的『選項總數』」**：本票把 `docs/ARCHITECTURE.md` 的
  15 更新為 **16**。#69 若先合併，後合併的那張照常解衝突——這個數字就是衝突點之一
  （兩票各 +1，合併後應為 17）。`src/README.md` 沒有總數，只有表格一列。
