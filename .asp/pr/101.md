# fix(panel): 匯出 CSV 的點擊攔在 window 捕獲階段——頁面層的連結攔截器不再把檔名吃掉

Closes #101

## 問題

#80 的匯出 CSV 內容正確，**檔名不對**：v0.4.0 發版前在 Grafana 12.4.12 實測，下載下來叫
`<uuid>.csv`，不是 `feedCsvFilename` 算出的 `augur-broadcast-<uid>-panel<id>-<時間>.csv`。
同一段程式碼貼到空白頁上得到的是正確檔名。

症狀本身就指出了成因：**uuid 正是 `blob:` URL 的路徑段**。也就是說瀏覽器確實打開了那個 blob，
但是在 `download` 屬性**沒被採用**的情況下打開的——典型成因只有一種形狀：頁面上有人接走了
這個 `<a>` 的點擊，`preventDefault()` 之後自己去導航 `href`。預設動作被取消，`download` 這個
「跟著連結走的時候要存成檔案、檔名用這個」的修飾語就一起失效，剩下的導航把 blob 的路徑當檔名。

## 攔截點在哪裡（AC-1 要的出處，含**我驗不到的那一半**）

Grafana 的頁面在 `document` 上掛了一個全域的連結攔截器，讓 dashboard 裡的 `<a href="/d/…">`
走 SPA 路由而不是整頁重載。依我對 Grafana 前端的認識，它是
`public/app/core/navigation/patch/interceptLinkClicks.ts` 的 `interceptLinkClicks`，
由 `public/app/app.ts` 以 `document.addEventListener('click', interceptLinkClicks)` 註冊
（**無第三引數 ⇒ 冒泡階段**），函式內部沿著 `e.target` 往上找最近的 `<a>`，命中就
`e.preventDefault()` 後交給 `locationService` 導航。

⚠️ **這一段我在本次出勤裡驗不到，不要當成已證實的事實。** worker 容器**沒有網路**
（`curl https://grafana.com/...` 回 exit 56），而 grafana/grafana 的原始碼不在容器內的任何
套件裡（`grep -rl interceptLinkClicks node_modules/ docs/ src/` 零命中；`@grafana/runtime`
只有編譯後的 dist，沒有 Grafana 自己的頁面程式碼）。契約也明文禁止存取 GitHub。
所以上面的檔名、函式名與**階段**是我的記憶，而不是行號級的引用——
**請主管層在重驗時順手確認**（做法見〈哪一層要靠實測〉第 1 點）。

票上留言 (b) 要求「指出那個 listener 的階段與它有沒有 preventDefault，因為那決定了能不能靠
事件傳播解決」。我同意這個判斷，但既然階段這件事我**證明不了**，就不把修法押在它上面：
**本 PR 的做法對兩個階段都成立**（下一節）。於是「出處是不是精確到行號」只影響這份描述的
可讀性，不影響修法的正確性——這是刻意的取捨。

另外保留一個**替代假說**（實測可一併排除）：若 panel 跑在 Plugin Frontend Sandbox 裡，
`download` 也可能是被沙箱政策擋掉而不是被 listener 擋掉。那種情況本 PR 無效，而且症狀相同。
README 已載明本 plugin 與沙箱不相容，實測環境應確認沙箱是關的。

## 做法

`downloadTextFile` 從 `src/components/MascotPanel.tsx` 搬到 **`src/dom/downloadTextFile.ts`**
（票文允許「必要時搬到獨立模組」）。搬家本身不改邏輯，目的是讓它有自己的測試落點——
它現在有事情值得被單獨測，而從元件那一側（`fireEvent.click` → React → 匯出鈕）摸不到
事件傳播這一層。邏輯的改動只有屏蔽那三行：

```ts
document.body.appendChild(a);          // Firefox 的條件，照舊（AC-2）
const shield = (e: Event) => {
  if (e.target === a) {
    e.stopImmediatePropagation();
  }
};
window.addEventListener('click', shield, true);   // ← 捕獲階段，掛在 window
try {
  a.click();
} finally {
  window.removeEventListener('click', shield, true);
  a.remove();
}
```

三件事各自的理由：

1. **掛在 `window` 而不是 `<a>`，而且是捕獲階段。** 捕獲的順序是
   `window → document → … → <a>`，**window 比 document 早**，所以不論頁面上那個攔截器掛在
   `document` 的捕獲還是冒泡階段，它都收不到這個事件。
   票文舉的示例做法（「讓這個 `<a>` 的點擊不要冒泡」）只擋得掉冒泡那一半——
   留言 (a) 說「`bubbles: false` 的 click 能讓測試轉綠而真實缺陷不動」，講的是同一件事，
   而本 PR 的測試正是**兩個階段各一支**（見 AC-3）。

2. **`stopImmediatePropagation()` 不會取消預設動作。** 取消預設動作的是 canceled flag
   （`preventDefault()`）；預設動作（跟著連結走 ＝ 這裡的下載）在派送迴圈**結束之後**才依那個
   flag 執行。容器內讀得到的實作佐證：
   `node_modules/jsdom/lib/jsdom/living/events/EventTarget-impl.js:250–255`——
   `if (activationTarget !== null) { if (!eventImpl._canceledFlag) { activationTarget._activationBehavior(…) } … }`，
   而兩個 stop-propagation flag 只在派送的 invoke 路徑裡被讀（同檔 `279`：`if (eventImpl._stopPropagationFlag) { return; }`；
   `364`：`if (eventImpl._stopImmediatePropagationFlag) { return found; }`），**沒有任何一處**參與上面那個
   activation 的判斷。
   jsdom 是照 DOM 標準的 dispatch 演算法實作的，這一條在本 PR 裡還有**行為**層面的證據：
   加了屏蔽之後 jsdom 照樣去「跟著連結走」（測試第 1、2 支的 `location.hash` 斷言）。
   用 `stopImmediatePropagation` 而不是 `stopPropagation`：前者連「同樣掛在 window 捕獲、
   但比我們晚註冊」的 listener 也一起停掉，成本為零。

3. **只吃 target 是自己那個 `<a>` 的事件、而且用完就解除。** 比我們早註冊的 window 捕獲 listener
   若在這段期間自己派送別的點擊，不該被我們吃掉（有測試）；漏掉解除的症狀很安靜——
   畫面上什麼都看不出來，只是每匯出一次就在 window 上多掛一個死 listener（也有測試）。

`<a>` 照舊 `document.body.appendChild` → `click()` → `remove()`，`revokeObjectURL` 照舊排在
下一個 task（AC-2 與留言 (c) 要的兩件事都有斷言，見下）。

### 留言 (a) 說的「測試可以通過而缺陷照舊存在」怎麼處理

三道：(i) 假攔截器**捕獲、冒泡各一支**，只擋冒泡的改法殺不過捕獲那一支；
(ii) 把 object URL 的替身做成**同文件 fragment**（`#augur-download-<n>`）而不是 `blob:`——
jsdom 對 hash 導航是實作了的，於是「預設動作到底有沒有發生」變成看得見的斷言
（`blob:` 在 jsdom 只會換來一行 `Not implemented: navigation` 的噪音，驗到的更少）；
(iii) 第 3 支落槌測試證明假攔截器不是稻草人。

## 單元測試驗到哪一層、哪一層要靠實測

**單元測試驗得到**（容器內沒有 Grafana、也沒有瀏覽器）：事件傳播與 DOM 屬性這一層——
攔截器收不到點擊（兩個階段）、點擊當下 `<a>` 的 `download`／`href`／在不在 document 裡、
預設動作沒被取消且 jsdom 真的跟著連結走了、object URL 的回收時機、屏蔽的作用域與解除。

**只能靠實測**（請用 v0.4.0 那套隔離環境，Grafana 12.4.12，Chrome）：

1. **AC-1 的 Then 本體**：按「匯出 CSV」，下載下來的檔名是
   `augur-broadcast-<uid>-panel<id>-<UTC 戳記>.csv` 而不是 `<uuid>.csv`。
   順手把本 PR 交不出來的那個出處補上：DevTools Console 跑
   `getEventListeners(document).click` 與 `getEventListeners(window).click`
   （Chrome 專有 API），看那個攔截器掛在哪個 target、`useCapture` 是 true 還是 false。
   若它是 **window 捕獲**，請把結論寫回票上——那正是下面第 2 點的殘餘風險。
2. **殘餘風險**：攔截器若掛在 **window 的捕獲階段、而且比本函式早註冊**，它仍會先收到事件，
   `preventDefault()` 一旦叫出去，這裡救不回來（檔名又是 uuid）。那種情況要換**投遞方式**：
   把 `<a>` 放進自己的 iframe document，讓頁面層的 listener 根本不在事件路徑上（留言 (b) 的建議）。
   **本 PR 刻意不預先做**：那條路在容器內一條斷言都驗不到（jsdom 的 iframe 不下載、
   跨 document 的 prototype 替身也接不上既有測試的攔截點），而「只在無法驗證的情況下才會跑的
   退路」正是最容易靜默壞掉的程式碼。實測若顯示檔名還是 uuid，請把這張票退回，
   第二版就走 iframe。
3. **替代假說的排除**：確認實測環境的 Plugin Frontend Sandbox 是關的（見上）。
4. **Firefox**：AC-2 的那個條件（`<a>` 要在 document 裡）本 PR 沒有改，但屏蔽是新東西，
   值得在 Firefox 上也按一次匯出確認檔名正確。
