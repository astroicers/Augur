# feat(core): 嚴重度別名對應——P1、sev1、disaster 這類 label 對到標準嚴重度

Closes #51

> 本票取代 #35（逾時重開）。**從最新 `main`（`2a0b782`）重做**，舊分支 `asp/35/work` 只當參考；
> `.asp/pr/35.md` 是被取代那一世的描述，一字未動。AC-6 的六項複審發現逐條處理在下方。

## 問題

`src/core/severity.ts` 的 `RANK` 只認 `critical`/`error`/`warning`/`info`/`unknown`。
很多組織的告警 label 是 `P1`、`sev1`、`disaster`、`high` —— 這些值查不到表 → 排名 0 →
被 UI 能選到的**任何**門檻擋掉，表情一律 `calm`。使用者看得到 Grafana 裡那則 critical，
吉祥物既不出聲也不變臉，而且不留任何錯誤。

## 做法

新增一個純模組 `src/core/severityAliases.ts`（票文允許「或新純模組」），三個匯出：

| 函式 | 做什麼 |
| --- | --- |
| `parseSeverityAliases(spec: unknown)` | 解析 `P1=critical, sev2=warning, disaster=critical` → `{ aliases, skipped }`。任何輸入都不拋 |
| `resolveSeverity(severity: unknown, aliases?)` | 命中別名 → 回對映的標準嚴重度；沒命中 → **原值原樣回傳**。空表／省略 = 恆等函式 |
| `describeSkippedAliases(skipped)` | 把被略過的項目講成一句話（供面板顯示或日後用）；沒有就回空字串 |

接線（最小改動）：

- `src/panelOptions.ts:25`：新增 `severityAliases?`，`DEFAULT_OPTIONS` 給 `''`。
- `src/module.ts:34`：`addTextInput`，排在「最低播報嚴重度」之後（它改變的正是那個門檻怎麼判），
  含一句說明與 `P1=critical, sev2=warning, disaster=critical` 的範例 + placeholder。
- `src/components/MascotPanel.tsx`（導播）：過濾前先 `resolveSeverity`，組句時把同一張表交給
  `buildBroadcastPlan`；紀錄那條 effect 也傳同一張表。兩條 effect 的相依陣列放的是**設定字串**
  （解析結果是 `Map`，每次 render 都是新參考，進 deps 會讓兩條 effect 每輪重跑）。
- `src/core/format.ts`：`buildBroadcastPlan(a, lang, aliases?)`，只用在 `emotion` 那一欄。
- `src/sources/history.ts`：`historyToEntries` 的 `opts` 多一個選填 `aliases`。

### 關鍵取捨一：別名以「前置正規化」生效，不給純函式加設定參數

AC-2 要求 `rankOf`/`meetsMin`/`severityToEmotion` 都以對應的標準嚴重度判斷。
本票**沒有**改那三個函式的簽章，而是在導播層先把值換掉再餵進去
（`meetsMin(resolveSeverity(a.severity, aliases), minSeverity)`）。理由：

1. 延續 2026-09-18 不擴 `Emotion` 那次裁定所依據的純函式語意 —— `severityToEmotion`
   只是 severity 的純函式（`src/avatar/AvatarController.ts:49` 的註解記著那次裁定的理由）。
   加一個 config 參數正是那條理由擋的事。
2. 「怎麼算同一個嚴重度」只能有一份定義。三個函式共用同一個入口，不會出現
   「排名吃別名、表情不吃」的不一致 —— 這與 #30 AC-4 把 `normalize` 收成單一事實源同一條理由。

機械證據：`severityAliases.test.ts` 直接斷言三個函式在同一次 `resolveSeverity` 之後的結果
（`rankOf(…)===rankOf('critical')`、`meetsMin(…,'warning')===true`、`severityToEmotion(…)==='critical'`），
並釘住 `severityToEmotion.length === 2`（簽章沒有多出參數）。

### 關鍵取捨二：播報句與 `BroadcastPlan.severity` 保留原始 label

別名只影響**判斷**（門檻、表情），不改念出來的字：告警上寫 `P1`，念成 `critical` 會讓聽到的人
對不上 Grafana 裡看到的那一則。`plan.text` 與 `plan.severity` 的既有行為一字未改
（`main` 上 #39 的 `speakableSeverity` 會把它正規化成小寫 `p1`，本票不介入那一層），有測試釘住。

### 關鍵取捨三：`severityAliases` 宣告成選填（`?`）

與 `MascotPanelOptions` 其他欄位「全必填」的慣例不同，刻意的：
AC-1 要求「既有測試不改」，而必填會讓既有的 `MascotPanelOptions` 字面值
（`MascotPanel.test.tsx` 的 `OPTIONS` fixture）全部得補一行。選填同時也更貼近執行期事實 ——
舊 dashboard 存下來的 panel JSON 沒有這個鍵。讀的那一側一律 `?? ''`，與 `ttsEndpoint` 同一招。
結果：**兩支既有測試檔的 diff 都是純新增（`git diff --numstat`：77+/0−、23+/0−），零行被改動。**

### 不加內建別名表（票文明文），也不開 ADR

- 不附內建表：猜一張表會改變現有使用者的行為（今天某個值走 unknown、升版後突然變 critical
  並開始出聲）。空設定 = 與先前完全相同，是本模組的第一條不變量。
- **不需要 ADR**：ADR 管的是架構決策。本票是一個 opt-in 的 panel 選項，零新相依、零後端、
  不動 `plugin.json`、不碰 ADR-004 的任何一條決策（threshold 仍走 standard field config、仍無後端），
  也沒有改 ADR-002 §1 事件契約的欄位語意（`BroadcastPlan` 的欄位與值域不變）。
  「不附內建別名表」是**實作層的取捨**，寫在 `severityAliases.ts` 檔頭與 `docs/ARCHITECTURE.md`〈設定〉。
