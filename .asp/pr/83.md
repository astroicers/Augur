# refactor(panel): 語音開關收成 useVoiceSwitch hook，補念佇列抽成純模組

Closes #83

## 問題

語音開關（ADR-007）在 `MascotPanel.tsx` 裡由四樣東西拼起來：

| 住處（本票之前） | 內容 |
| --- | --- |
| `const [muted, setMuted]` + `mutedRef` | 靜音狀態（一份給畫面、一份給**交付當下**讀） |
| `blockedRef`（`Array<{plan, at}>`） | 被 `not-allowed` 擋下的句子；寫入時修剪（窗內 + 同名只留最新） |
| `const [autoplayAck, setAutoplayAck]` | 外部語音被擋時使用者已經按過的那個聲線標籤（N1） |
| `applyMuted` / `toggleVoice` / `useEffect(watchMuted)` | 套用、按下、同頁與跨分頁同步 |

四樣東西之間有**順序依賴**，而那段順序只寫在元件裡：

1. `toggleVoice` 的被擋分支是「叫醒引擎 → 認下被擋的聲線標籤 → 清錯誤訊息 → **依時間順序**
   補念、同名只留最後一則 → 回報佇列長度」—— 五步，沒有任何一步有自己的測試；
2. `mutedRef` 必須在 `applyMuted` 裡**同步**更新，因為導播的 `muted()` 讀它、而同頁同步是在
   同一個 click 事件裡派送的（兩個 panel 的 `applyMuted` 在同一個 tick 裡跑完）；
3. 「只留 10 分鐘內」這個判斷**寫在兩個地方**（`onError` 的寫入側與 `toggleVoice` 的取出側），
   兩邊各自寫一次 `b.at >= now - BLOCKED_REPLAY_WINDOW_MS`，而**沒有任何測試釘住邊界**
   （剛好等於窗長時是留還是丟）。

**對外行為不變**：`MascotPanel.test.tsx` **一行都沒有改**（AC-4）。

### `blockedQueue`：三條行為各自有住處，邊界釘死

```ts
export const BLOCKED_REPLAY_WINDOW_MS = 10 * 60 * 1000;   // ADR-007 決策 2 的「10 分鐘」
createBlockedQueue({ now?, windowMs? }): BlockedQueue
  record(plan)   // 寫入時就修剪：丟掉過期的、同一個 plan.name 只留最新一筆
  take()         // 回傳窗內的那幾則（時間順序）**並整個清空**
  clear()        // 切到靜音走這條
  size()         // 目前留著幾筆
```

三個決定值得記：

- **窗長邊界明寫為「含」**：`at >= now - windowMs`，剛好等於窗長時**仍補念**。
  搬出來之前就是這一形（兩處各寫一次），現在兩處共用同一支 `within()`、而且邊界
  有**兩支**對打的測試（`邊界是「含」…仍補念` 與 `再多一毫秒就不補念了`）。
  票上留言 (c) 問的正是這一點。
- **`take()` 整個清空，連已經過期、不會被回傳的那幾則也丟**。這兩種實作都符合
  「取出後清空」的字面，差別只看得見在記憶體上 —— 所以 `size()` 進了 API，
  `連「已經過期、不會被回傳」的那幾則也一起清掉` 那一支才驗得到（留言 (c) 的另一半）。
- **同名去重只留在 `record` 一處**。原本的程式碼在寫入側與取出側**各做一次**
  （取出側是 `lastIndex` 那段）。`record` 是唯一的寫入口、它已經保證佇列裡每個
  `plan.name` 最多一筆，所以取出側那一份是**沒有任何測試殺得掉的死碼** ——
  我原本照搬了，變異測試 M5 證實它殺不掉（見〈變異測試〉），於是刪掉。
  刪掉之後「同名只留最後一則」只有一個住處，而破壞它的變異體（M4）會打紅 5 支測試
  （刪掉之前只打紅 1 支）。這是本票唯一一處**不是**逐字搬動的地方。

### `useVoiceSwitch`：那段順序變成一個函式

```ts
const { muted, blocked, isMuted, recordBlocked, noteVoiceName, toggle } = useVoiceSwitch({
  speaker, voiceName, speechErr,          // 讀
  onSilenced, onPending, onReplay,        // 寫回元件（注入）
});
```

- `muted` 給畫面；`isMuted()` 給導播的 `muted()`（**同步**讀 ref，不等 React 重繪）；
- `blocked` ＝「開著但瀏覽器擋著」，判定抽成純函式 `voiceBlockedBy({muted, speechErr, voiceName, autoplayAck})`；
- `toggle()` 被擋時是「叫醒 + 補念」，否則是「切換靜音 + `publishMuted`」；
- `recordBlocked(plan)` / `noteVoiceName(name)` 由播報器的 `onError` / `onVoice` 回呼餵進來。

**hook 不碰 avatar、不碰 feed、不碰導播**：要停嘴型／歸零 speaking 時呼叫 `onSilenced`、
要更新佇列長度時 `onPending`、補念前要清錯誤訊息時 `onReplay`。元件那一側因此只剩三個
接線 callback，而且它們**只碰 ref 與 setState**，所以 `useCallback([])` 是真的穩定、
靜音的訂閱只掛一次。

`muteStore`（#82）與 `blockedQueue` **都不被替身掉**：hook 直接呼叫
`readMuted`／`publishMuted`／`watchMuted` 與 `createBlockedQueue`，所以 hook 的測試
走的是 jsdom 真的 `localStorage` 與真的 storage／`MUTE_EVENT` 事件（票上留言 (d)）。
唯一的替身是 `Speaker` —— 它是瀏覽器語音引擎的邊界，jsdom 裡本來就沒有。

### 元件那一側的接線（全部的改動就這些）

```tsx
const currentSpeaker = useCallback(() => speakerRef.current, []);
const silenceAvatar = useCallback(() => { /* flap.stop / mouth 0 / speaking false */ }, []);
const clearSpeechErr = useCallback(() => setSpeechErr(null), []);
const { muted, blocked: voiceBlocked, isMuted, recordBlocked, noteVoiceName, toggle: toggleVoice } =
  useVoiceSwitch({ speaker: currentSpeaker, voiceName, speechErr,
                   onSilenced: silenceAvatar, onPending: setPending, onReplay: clearSpeechErr });

createBroadcastDirector({ …, muted: isMuted });     // 原本是 () => mutedRef.current
onVoice: (name) => { setVoiceName(name); noteVoiceName(name); },
onError: (e, plan) => { if (e === 'not-allowed' && plan && !PREVIEW_PLANS.has(plan)) { recordBlocked(plan); } … },
onClick={() => toggleVoice()}                        // 原本是 toggleVoice(voiceBlocked)
```

試聽的 `PREVIEW_PLANS` **刻意留在元件**：那是「試聽」的身分，不是語音開關的事
（F7 的「以物件身分辨識」由元件這一側判斷，hook 只收到該收的那幾則）。

播報器那個 effect 的相依陣列多了 `noteVoiceName` 與 `recordBlocked` —— 兩者都是
`useCallback([])`、referentially 穩定，所以該 effect 的重跑時機**一個字沒變**
（這一條由既有的 `播報中改語音選項（播報器重建）…`、`音高與語速傳得進播報器`
與 `#51`／`#63`／`#64` 那幾組測試一起守著，全綠）。

## 票上留言的判讀

兩則留言的作者 `asp-ng-supervisor-legacy[bot]` **不是 repo collaborator**，依 §10 僅供參考、
不是 AC 的權威來源。本票照**票文**做，四點 AC 建議的處置：

- **(a) 可 grep 的終局斷言** —— **採納，而且寫成自動化測試**（三支，見〈AC-2 的數字〉）。
  留言的觀察是對的：「數量減少」搬一個就成立。放的位置與 #82 不同，理由寫在那一節。
- **(b) AC-4 逐支寫出測試名稱** —— 採納，見〈AC-4：語音開關相關的那幾支〉（15 支）。
  留言指出的 F1 標籤漂移**在本副本上覆核過**：`:845` 的 F1 是播報器重建、與語音開關無關，
  語音開關那支 F1 在 `:1121`。
- **(c) AC-1 的邊界** —— 採納：窗長邊界明寫為**含**（`at >= cutoff`），兩支對打的測試
  （含／多一毫秒）；「取出後清空」明寫為**連過期的一起清**，由 `size()` 驗得到。
  M1／M3 確認兩者都抓得到（M1 只有一支抓得到，已在表上誠實記）。
- **(d) 至少一條測試走真實 `muteStore`** —— 採納，而且**整個 hook 測試檔都不替身 `muteStore`**：
  11 支決策 1 的測試走 jsdom 真的 `localStorage` 與真的 `storage`／`MUTE_EVENT` 事件。
  `blockedQueue` 同樣不替身。唯一的替身是 `Speaker`（瀏覽器語音引擎的邊界）。

留言 2 是**拆票建議**，明文「未經人裁」。本票**維持一張票**，理由與留言自己提的一致：
兩步都改同一個 `MascotPanel.tsx` 的同一塊（`blockedRef` 的寫入側在播報器的 `onError` 裡、
