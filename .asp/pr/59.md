# refactor(speech): 斷句規則先以共用語料寫 golden 測試,再把兩份 TS 實作集中

Closes #59

## 問題

斷句切點有三份實作、彼此不同,而且**沒有任何測試釘住差異**:

| | `speaker.ts` `splitForRemoteVoice` | `remoteSpeaker.ts` `splitClauses` | `tools/tts-server/textsplit.py` |
| --- | --- | --- | --- |
| 切點正規式 | `(?<=[，。！？；、\s])｜(?<=[,.;?!])(?![\d/])` | `(?<=[，：；。！？]｜[,:;?!](?![\d/]))` | `(?<=[，：；。！？])｜(?<=[,:;?!])(?<!\[:)(?![\d/])` |

改其中一份、另外兩份靜默分岔。本票**先寫 golden 測試、再集中**,行為一字不變。

## 做法

1. **語料** `src/speech/__fixtures__/split-corpus.json` —— **41 句**,每句附三份實作現在的輸出。
   以現行實作產出後逐句人工複核,可疑的 **7 句**帶 `suspect` 欄位(見下方〈人工複核〉)。
2. **golden 測試** `src/speech/__tests__/splitCorpus.test.ts`(**101 支**)與
   `tools/tts-server/test_textsplit.py` 的 `語料至少二十五句`／`語料逐句比對`(**+2 支**)讀同一份檔案。
3. **集中模組** `src/speech/splitRules.ts` —— 共用的切點字元與「數字或 `/` 前不切」收成具名常數,
   兩個函式各自的差異也是具名常數;檔頭逐條記下三份的差異與出處(AC-5)。Python 一字未改。

### 關鍵取捨一:集中「切點」,不集中「聚合」

`splitRules.ts` 只收**哪些位置可以切**。`splitForRemoteVoice` 的「每段不超過 N 字、超長硬切」與
`splitClauses` 的「不足 16 字併進下一段」留在各自的檔案裡 —— 一個是上限、一個是下限,
演算法沒有共用的部分,硬湊一個共用函式只會多一層參數。
AC-3 要求集中的是「正規式常數與『數字或 `/` 前不切』這類條件」,正是這一層。

### 關鍵取捨二:用 `new RegExp` 串具名常數,不用正規式字面值

```ts
export const REMOTE_VOICE_SPLIT_POINT = new RegExp(
  `(?<=[${SHARED_FULLWIDTH}${REMOTE_VOICE_ONLY_FULLWIDTH}${REMOTE_VOICE_ONLY_WHITESPACE}])` +
    `|(?<=[${SHARED_ASCII}${REMOTE_VOICE_ONLY_ASCII}])${NOT_BEFORE_DIGIT_OR_SLASH}`
);
```

字面值沒辦法讓「共用的部分」與「各自的差異」在型別與 `grep` 上分開。代價是字元類別裡的順序變了
(`[,.;?!]` → `[,;?!.]`),集合相同、語意相同。**不是靠眼睛判斷相同**:

- 以 33 個與規則相關的字元(全形／半形標點、數字、`/`、`\`、`[`、`]`、空白、換行、emoji、漢字)
  窮舉長度 1–3 的所有字串共 **40,494** 個,新舊兩版正規式的 `String.split` 結果**逐字相同**。
  兩個正規式的 lookbehind／lookahead 都只看前後各一個字元,長度 3 已覆蓋所有上下文組合。
- 既有的 `speaker`／`remoteSpeaker` 測試**一行未改**全綠(`git diff` 不含那兩支檔案)。

### 關鍵取捨三:語料用 `readFileSync` 讀,不用 `import`

不必為一個 fixture 打開 `resolveJsonModule`,也讓語料不進任何 runtime 模組圖。
Python 端同樣只讀檔(`Path(__file__).resolve().parents[2]`),兩邊沒有共用的程式碼、只共用那份檔案。

### 關鍵取捨四:語料帶一句 lone surrogate 的輸出

`emoji-limit-1`(上限 1、文字 `a😀b`)的真實輸出是 `["a","\ud83d","\ude00","b"]` ——
一個 emoji 本身就超過上限時,`speaker.ts` 的代理對守衛(`end - 1 > i`)不成立,只能切在代理對中間。
那是現行行為,照實記。JSON 以 `\ud83d` 轉義存放;Python 端只讀 `text`／`minChars`／`pythonClauses`,
不碰也不重新編碼那一欄(utf-8 無法編碼單獨的代理字元,碰了會炸)。這一條寫在語料的 `about` 與 Python 的註解裡。

## 人工複核(採納留言 1 的建議)

留言 1 的作者**不是** repo collaborator,依契約僅供參考、不是 AC。但它指出的風險是真的
(「直接把跑出來的結果當 golden 就會把既有缺陷凍成唯一事實源」),成本也低,所以**照它做了**:
語料以現行實作產出後逐句人工複核,可疑的句子帶 `suspect`(`severity` / `why` / `whyNotFixedHere`)。
一句都沒有默默照抄、也一句都沒有默默修正 —— 本票不改行為是票文明訂的。

| 語料 id | 嚴重度 | 可疑之處 |
| --- | --- | --- |
| `ipv6` | **高** | `splitClauses` 與 Python 在 `fe80::1ff:` 的第二個冒號後切開(冒號後面是 `f`,不是數字也不是 `/`),IPv6 位址被拆成**兩次請求**、中間多一個停頓。`4c8c5fd`(第二輪複審 R2)就是為 IPv6 與 `C:\` 把半形冒號從 `splitForRemoteVoice` 的切點移除的,**同一條理由從未套用到另外兩份** |
| `windows-path-visible-split` | **高** | 同一條的另一半:`C:` 後面是反斜線,不在 `(?![\d/])` 的保護範圍內 → `受影響的磁碟是 C:` ／ `\Data\logs，請清理。` 被切成兩段。語料裡另附 `windows-path`,上限／下限不同時聚合層會把這個差別抹平 —— 兩種都留著,免得下一個人以為「`C:\` 沒事」 |
| `url-http-en` | 中 | `splitForRemoteVoice` 把 `http://grafana.local` 在 `grafana.` 後面當切點(守衛只擋「點後面是數字或 `/`」,擋不住 `local`)。`textsplit.py` 的註解(`d135467`)記下不切半形句點的理由正是「`91.35`、`grafana.local`」—— 同一個理由在 `speaker.ts` 上沒被採用。只影響多一個停頓,文字內容不變 |
| `empty` | 低 | `splitClauses('')` 回 `['']` → 空字串的一則會送出一次 `input: ""` 的請求;Python 回 `[]`。現行面板不會產生空的播報文字,觀察不到。既有測試已把 `['']` 釘住,改它會動到 AC-4 要求一行不改的測試 |
| `trailing-space` | 低 | `splitClauses` 的 `.filter((s) => s.trim() !== '')` 把只有空白的片段整個丟掉 → 切出來的句子接起來**不等於**原文。中途降級時 `remoteSpeaker` 用 `clauses.slice(from).join('')` 組剩下的文字,被丟掉的字元不會交給 Web Speech。實務上丟的只有空白,但這是 `splitForRemoteVoice` 明文保證、而 `splitClauses` 沒有的不變量 |
| `leading-trailing-space` | 低 | 同上,外加 Python 對每一段 `.strip()` —— 三份的前後空白處理各不相同 |
| `bopomofo-tag` | 低 | Python 有 `(?<!\[:)` 不在注音標註裡切(`d135467` 第三輪複審 P2),`splitClauses` 沒有 → `点[:` 後面會被切開。注音標註是前一個模型 BreezyVoice 的前處理產物,面板端從來不產生它,所以現行輸入上觀察不到 |

**這 7 條本票都不修**(票文:行為一律不變;AC-4:輸出逐字相同)。要修哪一條,先改語料、再改實作。

### 18 個變異全數轉紅

改 `splitRules.ts` 的一個常數、跑 `npx jest src/speech`,括號內是轉紅的測試數:

拿掉遠端聲線的頓號(1)、空白(2)、半形句點(1);把半形冒號放回遠端聲線切點(2,即 `4c8c5fd` R2 的回歸);
句子端不切全形冒號(1)、不切半形冒號(2);把頓號(1)或半形句點(1)加進句子端切點;
拿掉數字或 `/` 守衛(3);共用集合各少一個字元 —— 全形 `，`(2)`。`(2)`！`(1)`？`(1)`；`(1)、半形 `,`(2)`;`(1)`?`(1)`!`(1)。

> 這一輪抓到兩個**原本存活**的變異並補了語料:頓號與全形分號的差異在原先選的上限／下限下被聚合層抹平
> (切點真的變了、輸出卻一樣)。補 `ideographic-comma-forced`、`fullwidth-punct-sweep`、`ascii-punct-sweep`
> 三句、把 `fullwidth-colon` 的下限從 8 改成 4 之後全數轉紅。這正是「測試名稱說得比斷言多」的那類債,

## 未能在本次驗證的部分(誠實記)

- **語料檔會被打包進 `dist/`**(28 KB)。腳手架的 `.config/bundler/copyFiles.ts` 有一條
  `{ from: '**/*.json', to: '.' }`,`src/` 底下任何 `.json` 都會複製進去,所以
  `dist/speech/__fixtures__/split-corpus.json` 會跟著外流。**沒有繞過**:AC-1 指名這個路徑、
  `.config/` 禁止手改、`package.json` 不能動(所以也不能加根層 webpack wrapper 改 script 指向)。
  影響是 plugin 包多 28 KB(同一個包裡已有一張 766 KB 的 sprite),不影響執行期行為;
  `node tools/check-bundle-deps.mjs` 仍 PASS、`tools/check-js-suffix.sh` 仍 OK。
  要清掉的話是另一張票(改 copy pattern 或把 fixture 移出 `src/`)。
- **`tools/asp-test.sh` 整道閘沒跑**:容器內沒有 `jq`,腳本第一步就 `exit 1`
  (`asp-test: jq 不存在，無法產生測試痕跡`)。改用逐項手跑覆蓋本票碰到的範圍:
  `typecheck`、`lint`、`jest`(464/464)、`build`、`test_textsplit.py`(15/15)、
  `check-js-suffix.sh`、`check-bundle-deps.mjs`。未跑的 sprite／monitoring／stroke-battery／
  grafana-version 幾段,本票一個輸入檔都沒碰。
- **e2e 未跑**:需要 live Grafana(容器內無 docker),本票也沒有新增 e2e 面。
- **實機沒聽過**:切段與斷句的差別要戴耳機聽才感覺得到,起不了 Grafana。本票的保證是
  「輸出逐字與重構前相同」,這一點由 golden 測試 + 既有測試零改動 + 窮舉等價 + 18 個變異擋住。
- **三份沒有真的合成一份**:票文要的是「共用的切點規則集中在單一模組」,不是三份行為統一。
  Python 不 import TypeScript,語言邊界兩邊只能共用語料;而 7 條 `suspect` 正是「統一」要先決定的事,
  那是另一張票。
