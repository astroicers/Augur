# fix(feed): 被抑制的標記在合併時轉到紀錄列,不再跟著本分頁那一列一起消失

Closes #99

## 問題

#81 在清單列上加了「抖動中,未念」「靜音時段,未念」兩種標記,但 v0.4.0 發版前實測
(Grafana 12.4.12)時標記**看不到**:那個 panel 有播報紀錄。

`buildFeedRows` 的合併規則是「同一件事兩邊都有時只留紀錄那一列」,而 `suppressed` 只掛在
本分頁那一列上,於是跟著被丟掉。#81 的 PR 把這點寫成已知取捨;但真實部署幾乎都有狀態歷史
(EKS 值班台就是),所以那個取捨實際上等於「標記幾乎不會出現」。

## 做法

只改 `src/feed/feedRows.ts` 的合併那一段:**比對鍵與窗長一字不動**,只改「留下的那一列帶誰的
`suppressed`」。

原本的 `sessionOnly` 是一個 `feed.filter(... .some(...))`;現在把它和「每一筆紀錄要帶誰的原因」
收成同一次比對 `mergeSession(feed, entries)`,回傳 `{ sessionOnly, suppressed }`
(`suppressed` 與 `entries` 同長同索引)。分成兩個迴圈算就可能一邊說「這一列被紀錄取代了」、
另一邊說「沒有本分頁列對得上」。

比對本身抽成 `sameEvent(entry, line)`,**合併與原因轉移讀的是同一個判定**。這是刻意的:
把比對窗(`SESSION_MATCH_WINDOW_MS`)放寬、或另開一套比對鍵,也能讓標記「出現」而單元測試
照樣綠 —— 代價是久遠的紀錄被誤標成本分頁抑制的。有一支測試(AC-2 的窗外那支)釘住這條路。

轉移規則(票文只裁定了一對一的情形,以下兩個分岔是本票補的,理由寫在原始碼註解裡):

| 情形 | 行為 |
| --- | --- |
| 一句本分頁的話對上一筆紀錄 | 原因轉到那一筆紀錄列上(AC-1) |
| 紀錄列沒有本分頁的話對得上 | 不帶原因(AC-2),**不猜** |
| **多對一**:窗內兩句話對上同一筆紀錄(先抖動抑制、後進靜音時段) | 取**時間最接近**那一筆紀錄的那一句的原因;同距離取 `feed` 裡較前面的(呼叫端維持「新的在前」,即較新的) |
| 多對一,而最近的那一句**其實念了** | 不帶標記,而**不是**從較遠的那一句撿一個原因來標 —— 那會謊稱沒念 |
| **一對多**:窗內兩筆紀錄都對得上同一句 | 標記只出現在最接近的那一筆上。一次被抑制的播報在畫面上就該是一個標記,兩筆都標會讓人以為被擋了兩次 |

`MascotPanel.tsx` **一行未改**(票文範圍):它的 `data-suppressed={r.suppressed}` 本來就不看
`origin`,所以紀錄列一拿到原因就會渲染標記與 `title`。

## AC 逐條對照

### AC-1:被紀錄列取代時帶著同一個 `suppressed` ✅

`mergeSession` 把被取代掉那一句的 `suppressed` 轉到紀錄列上。四支測試:
`quiet` 一支、`flapping` 一支(AC-4 的「兩種原因各一支」)、「轉移的是原樣的那個原因而不是布林」
一支、「念出去的那一句被取代時紀錄列不會多出標記」一支。

### AC-2:紀錄列沒有對應的本分頁列 → 不帶 `suppressed` ✅

`suppressed` 初值是 `entries.map(() => undefined)`,只有比對上的索引會被寫入。三支測試:
空 feed(分頁打開之前就發生的事)、同文字但時間在窗外、時間在窗內但文字不同。

### AC-3:篩選結果不變 ✅;CSV **沒有**加欄位

- `suppressed` **不進** `search` —— 篩選讀的還是 `e.search`(句子＋label 值,`history.ts` 產生),
  與本票之前逐字相同。測試:同一份輸入在 `['', 'diskfull', 'db-01', 'memhigh', 'quiet',
  'flapping', 'zzz']` 七個查詢字下,把「不帶標記的同一份 feed」當基準線,逐列比對
  `key / origin / text / at / when` 與 `emptyText`;另加一支「沒有任何列帶標記時輸出不變」的迴歸面。
  注意其中 `'quiet'`、`'flapping'` 兩個查詢字是刻意的:原因字串**查不到**那一列。
- **CSV 沒有加這一欄**:`feedCsv.ts` 一行未改,仍是 `時間(ISO 8601,UTC) / 來源 / 句子` 三欄
  (`src/README.md` 的「The marks are **not** in the CSV export: its three columns are
  unchanged.」依然成立)。#80 的匯出因此只間接受益於「篩選結果不變」。

### AC-4:測試與 `src/README.md` ⚠️ 一處做不到,說明如下

- 三類測試都有,而且比要求多:見上面 AC-1／AC-2／AC-3,外加多對一、一對多、純函式各一支。
  `src/feed/__tests__/feedRows.test.ts` 新增 `describe('#99: ...')` 共 **13 支**。
- **「既有 `feedRows` 測試一行不改」做不到,刪掉了一支。** 既有測試裡有一支
  `#81：…› 被紀錄列吃掉的那一句,標記跟著消失(合併窗內只留紀錄那一列)`,它斷言的正是
  AC-1 要改掉的那個行為 —— 這兩條在邏輯上不能同時成立。處理方式:
  **刪掉那一支**(它的情境由 `#99 › AC-1 …靜音時段`／`…抖動抑制` 兩支以新行為接手),
  `feedRows.test.ts` 其餘每一支**逐字未改**,斷言一條也沒放寬。
  其中 `#81 › 紀錄模式:補進來的本分頁那一列照樣帶著標記,紀錄列一律沒有標記` 這一支照樣綠
  (它的紀錄列沒有本分頁列對得上,走 AC-2),但**標題後半已不再是普遍成立的敘述** ——
  按「一行不改」留著原文,不改標題。
- `src/README.md`「Three honest limits」第一條改寫:「mark disappears with the session line」
  → 標記**移到**紀錄列(「這個分頁沒念這件事」不因換哪一列顯示而改變),並補上 AC-2
  那一半(沒有本分頁列對得上的紀錄列 —— 也就是紀錄裡的絕大多數 —— 永遠不標,不猜)
  與「比對不變」一句。項目標題從 "Only lines this browser tab produced can carry a mark"
  改成 "Only decisions this browser tab made can be marked" —— 原標題在新行為下是錯的。

### 單元測試驗到哪一層、哪一層要靠實測

- **單元測試驗到**:`buildFeedRows` 的輸出 —— 哪一列帶哪一個 `suppressed`、多對一／一對多的
  分岔、篩選結果不變、純函式。這是本缺陷的根因所在那一層。
- **要靠實測**:`suppressed` → `data-suppressed` → 中文／英文標記字串**在真實 Grafana 裡
  長出來**那一段。`MascotPanel.tsx` 未改,`MascotPanel.test.tsx` 既有的三支
  `#81 AC-1` 接線測試(jsdom)跑的是沒有紀錄的路徑,所以「有紀錄的 panel 上標記真的看得見」
  這件事沒有自動化證據。
- **複現步驟**(給主管層重驗用;「標記沒出現」與「這次剛好沒有紀錄」長得一樣,所以條件要齊):
  1. 隔離環境 Grafana **12.4.12**,panel 設 *Quiet hours* 涵蓋現在的時刻,
     *Still speak critical in quiet hours* 不勾(或改用 warning 級別的規則)。
  2. 讓 **P2** 的 warning 規則進入 firing,確認**沒有聲音**。
  3. **確認該 panel 讀得到狀態歷史**(清單上有 `data-origin="history"` 的列) ——
     這一步是關鍵前提,沒有紀錄時本缺陷本來就看不見。
  4. 預期:講同一件事的那一列是紀錄列,而且它帶 `data-suppressed="quiet"`
     並寫出「靜音時段,未念」。修復前該列沒有任何標記。
  5. 抖動那一側同樣走一次(*Flapping suppression: flip threshold* 設 4、窗 10 分鐘),
     預期 `data-suppressed="flapping"`。
