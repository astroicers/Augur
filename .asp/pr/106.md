# chore(github): issue 表單加「依賴(depends-on)」欄位——讓 runtime 讀得到票與票的先後

Closes #106

## 做了什麼

`task.yml` 與 `bug.yml` 各加一個非必填 `textarea`,id 都是 `depends-on`,位置**緊接 `ac` 之後、
`links` 之前**(兩份表單同一順序),label 是「依賴(depends-on)」。description 寫明每個依賴一行
`depends-on: #N`、沒有依賴就留空,並把三件開票人會踩的事寫在輸入框旁邊:runtime 的比對格式、
「依賴 #69」/「#69」不會被認得(#70 → PR #75 的事故)、留空時的 `_No response_` 不算依賴。
placeholder 就是逐字可用的 `depends-on: #69`。

`config.yml` 的檔頭註解原本只交代「兩套表單的 AC 欄必填 Given/When/Then」,同步加上依賴欄的說明,
並補一句 blank issue 路徑走不到這個欄位、依賴只能手寫(見下方 AC-4)。

`.asp-fact-check.md` 補第一列(該檔被 `.gitignore:9` 排除,**不在本 PR 的檔案清單內**,見 AC-2)。

不改 `src/`,不改 `package.json`/lockfile、`.config/`、`.asp/`(除本描述檔)、`asp-ci.yml`、
`tools/asp-test.sh`,沒有新增相依。版控側淨改動:3 檔、+26/−0 行(既有的每一行都沒動,只插入)。

## AC 逐條對照

### AC-1 ✅ 兩份表單都有「依賴(depends-on)」欄位

| 要求 | 實作 |
| --- | --- |
| 型別 `textarea`、非必填 | `type: textarea`,**沒有** `validations: {required: true}`(`task.yml:16-26`、`bug.yml:16-26`) |
| 放在「驗收準則」之後 | 緊接 `id: ac` 之後、`id: links` 之前。兩份表單的欄位順序:task = `background, ac, depends-on, links`;bug = `repro, ac, depends-on, links, defect-class` |
| `description` 寫明格式 | 「每個依賴一行,整行就是 `depends-on: #N`(N 是本 repo 的票號);沒有依賴就留空。」後接 runtime 的比對規則與兩個反例 |
| `placeholder` 逐字可用 | `placeholder: "depends-on: #69"` ——**逐字**,複製貼上即符合正規式(AC-2 已實測) |

**位置釘得比字面更死**(採留言 1(c)):AC-1 只說「驗收準則之後」,而兩份表單在 `ac` 之後都還有欄位
(`links`;bug 另有 `defect-class`),擺最後也符合字面。選「緊接 `ac`、`links` 之前」的理由是人看的
一致性 —— 機器不在乎順序,人在兩份表單間切換時會踩空。

### AC-2 ⚠️ 正規式實測命中;**官方文件出處無法實連**,逐條交代

**先講做到的部分。** 本地模擬(讀出表單的 placeholder,按 `### <label>` + 空行 + 原值組成票文,
用 asp-ng `launcher.py` 的 `_DEPENDS_ON = ^\s*depends-on:\s*#(\d+)`、`IGNORECASE`、逐行比對):

```
### 依賴(depends-on)

depends-on: #69
```

| 輸入 | `_DEPENDS_ON.match` |
| --- | --- |
| `depends-on: #69`(placeholder 逐字) | ✅ 命中,group(1) = `69` |

| `依賴 #69` | ❌ 不命中 |
| `#69` | ❌ 不命中 |
| `depends on #69`(漏連字號) | ❌ 不命中 |

(d)② 的 `_No response_` 已寫進欄位 description,開票的人在表單上就看得到「留空不算填錯」。

### AC-3 ✅ 兩份 YAML 解析不報錯、`id` 在同一份表單內不重複

票文那條命令照跑:

```
$ python3 -c 'import yaml,sys; [yaml.safe_load(open(f)) for f in sys.argv[1:]]' \
    .github/ISSUE_TEMPLATE/task.yml .github/ISSUE_TEMPLATE/bug.yml
$ echo $?
0
```

但留言 1(b) 是對的:**這條命令驗不到 Then 的後半句**。實證 —— 把 `depends-on` 的 id 改成 `ac`
(同一份表單兩個 `id: ac`)再跑同一條命令,`exit = 0`,ids 讀出來是
`['background', 'ac', 'ac', 'links']`。所以補一條把斷言寫進命令本身的版本,不符就非零退出:

```python
python3 - .github/ISSUE_TEMPLATE/task.yml .github/ISSUE_TEMPLATE/bug.yml <<'PY'
import sys, yaml
bad = False
for f in sys.argv[1:]:
    ids = [e['id'] for e in yaml.safe_load(open(f, encoding='utf-8'))['body'] if 'id' in e]
    print(('OK  ' if len(ids) == len(set(ids)) else 'DUP '), f, ids)
    bad |= len(ids) != len(set(ids))
sys.exit(1 if bad else 0)
PY
```

實跑輸出:

```
OK   .github/ISSUE_TEMPLATE/task.yml ['background', 'ac', 'depends-on', 'links']
OK   .github/ISSUE_TEMPLATE/bug.yml ['repro', 'ac', 'depends-on', 'links', 'defect-class']
exit = 0
```

對那個刻意做壞的變異體,這一版回 `DUP` 並 `exit = 1` —— 斷言真的在擋。
`config.yml` 也另外解析過一次(它不是表單,沒有 `body`/`id`)。

> 這條命令**沒有**寫進 `tools/asp-test.sh` 或 CI:契約明文「不要改 `tools/asp-test.sh`」、
> 共同驗收明文不改 `asp-ci.yml`。要讓它常駐是另一題(加進 `ci.yml` 的一個 step),需要一句裁定。

### AC-4 ✅ 條件成立,所以**加了**;並一併交代 blank issue 路徑

AC-4 寫「若提到兩套表單的欄位就同步加一句,沒提到就不改」。**本 repo 的條件已經成立** ——
`config.yml:1` 的檔頭註解原文是「task / bug 兩套表單的 AC 欄必填 Given/When/Then」,那就是在講
兩套表單的欄位。採留言 1(a),沒有把它解讀成「沒提到」而靜默跳過。加的兩段:

1. 緊接那一行之後,寫依賴欄非必填、格式 `depends-on: #N`、runtime 只認這個格式、寫散文不會被認得。
2. 一段 ⚠️ :`blank_issues_enabled: true` 與 contact_links 把想法階段的票導去 blank issue,
   **那條路徑沒有表單、走不到新欄位**,依賴只能自己手寫那一行;提醒 triage 補 AC 時一併補。
   這是留言 1(a) 後半段指出的缺口 —— 不寫,#70 那類事故會從 blank issue 再發生一次。

`blank_issues_enabled` 與 contact_links 的**行為一個字都沒動**(把 blank issue 關掉是 ASP 入口
政策,不是本票的範圍)。
