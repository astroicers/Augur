# chore(github): issue 表單加「依賴(depends-on)」欄位——讓 runtime 讀得到票與票的先後

Closes #109

(取代 #106 / PR #108。本票 AC 與 #106 逐字相同,以新時鐘重做。)

## 問題

Augur 的兩份 issue 表單沒有「依賴」欄位,票文只能用散文寫先後關係。2026-10-15 的實錄:
Augur#70 的票文寫「依賴 #69……請在那張票合併後再開工」,沒有機器讀得到的那一行,
runtime 照常派工,在 #69 合併前就產出 PR #75,之後撞上 base 衝突(asp-ng #992 的起因)。

asp-ng 的 runtime 認的是**整行以 `depends-on: #N` 開頭**(票文引述 asp-ng `launcher.py`
的 `_DEPENDS_ON`:`^\s*depends-on:\s*#(\d+)`,不分大小寫、逐行比對)。本票就是 asp-ng #992
AC-4 說的「消費端表單各自補欄位」裡 Augur 的那一張。

## 做法

`.github/ISSUE_TEMPLATE/task.yml` 與 `bug.yml` 各加同一個欄位,**緊接 `ac` 之後、`links` 之前**:

```yaml
  - type: textarea
    id: depends-on
    attributes:
      label: 依賴(depends-on)
      description: >-
        每個依賴一行 `depends-on: #N`(N 是本 repo 的票號);沒有依賴就留空。
        runtime 只認「整行以 depends-on: #N 開頭」的那一行:寫成「依賴 #69」或只寫 `#69` 不會被認得。
      placeholder: "depends-on: #69"
```

兩份逐字相同(diff 可見兩個 hunk 內容一致),沒有 `validations`(即非必填),沒有 `render:`。
`.github/ISSUE_TEMPLATE/config.yml` 的檔頭說明同步補上這個欄位,並交代 blank issue 那條路徑。

`src/` 一行未動。

## AC 逐條對照

### AC-1 — 兩份表單都有「依賴(depends-on)」欄位 ✅

| 要求 | task.yml | bug.yml |
| --- | --- | --- |
| 型別 `textarea` | ✅ | ✅ |
| 非必填(無 `validations`) | ✅ | ✅ |
| 放在「驗收準則」之後 | ✅ body 索引 1(`ac`)→ **2(`depends-on`)** → 3(`links`) | ✅ 同樣 1 → **2** → 3(其後 4 是 `defect-class`) |
| `description` 寫明格式(一行一個 `depends-on: #N`、沒有就留空) | ✅ | ✅ |
| `placeholder` 逐字可用:`depends-on: #69` | ✅ | ✅ |

位置釘在**緊接 `ac` 之後、`links` 之前**:票文字面只說「驗收準則之後」,而兩份表單在 `ac`
之後都還有欄位(task 的 `links`;bug 的 `links`、`defect-class`),擺最後也符合字面。
選緊接其後,因為「做什麼」與「什麼先做完」讀起來是同一件事,且兩份表單這樣擺位置一致。

### AC-2 — 使用者填 `depends-on: #69`,票文裡有整行就是它的一行 ⚠️ 部分達成(渲染端未判定)

兩端拆開講,因為只有一端在本票內驗得到:

**(i) 正規式這一端 — ✅ 本機實測。** 以票文引述的 `^\s*depends-on:\s*#(\d+)`(IGNORECASE、逐行)
跑 `python3 re`,餵的是**本 PR 實際寫進 YAML 的 placeholder 字串本身**,不是我自己組的票文:

| 輸入行 | 結果 |
| --- | --- |
| `depends-on: #69`(placeholder 逐字) | MATCH,group(1)=`69` |
| `  depends-on: #69` | MATCH |
| `Depends-On: #69` | MATCH |
| `depends-on: #69` + `depends-on: #70` 兩行 | MATCH 兩筆(`69`、`70`),證 description 教的「一行一個」可行 |
| `依賴 #69` | 不 match(與票文一致) |
| `#69` | 不 match |
| `見 depends-on: #69` | 不 match(整行不是以它開頭) |
| `_No response_` | 不 match |

這條只證「**若** 正規式如票文所述,**則** 這個 placeholder 命中它」。正規式本身的逐字性
來自票文對 asp-ng 原始碼的引述——本容器沒有 asp-ng 的 `launcher.py`,**未在本票內查證**。

**(ii) GitHub 渲染這一端 — ⛔ 未判定,照上一輪 reviewer 的 medium 明標。**
官方文件查得到的是「回應會被轉成 markdown 加進 issue 的 body」與「不給 `render:` 就不會被包成
codeblock」(逐字引用見下節);**查不到**「欄標題渲染成 `### <label>`、回應自成一個獨立段落」
這個形狀的官方載明。容器內也沒有 GitHub 存取,無法開一張票實測。所以 AC-2 的 Then
(「票文裡有一行整行就是 `depends-on: #69`」)在本 PR 裡**只有官方文件的間接支持,沒有實測**。
我沒有用「自己組一段票文再拿正規式去比對」來補這個缺口——那是循環論證,正是上一輪被提的那一點。

**合併後的一次性驗證建議(人工,30 秒)**:用新表單開一張測試票,`depends-on` 欄填
`depends-on: #69`,送出後看 raw body(`?plain=1` 或 API)那一行是否整行就是它;順手看留空時
該欄標題下出現什麼。驗完把結果記回 ROADMAP 或後續票。

### AC-3 — 兩份 YAML 解析不報錯、`id` 不重複 ✅

票文給的 one-liner:

```
$ python3 -c 'import yaml,sys; [yaml.safe_load(open(f)) for f in sys.argv[1:]]' \
    .github/ISSUE_TEMPLATE/task.yml .github/ISSUE_TEMPLATE/bug.yml
$ echo $?
0
```

**但這條命令只驗得到 Then 的前半句。** 它只做 `safe_load`,驗不到「`id` 不重複」——同一份表單裡
兩個同名 `id` 在 YAML 裡是兩個獨立的 list item,parse 照樣成功、退出碼照樣 0。上一輪 reviewer 的
low 已裁定「這類斷言的自動化不在本票範圍、PR 內註明即可」,所以後半句在這裡以清單 + 聲明交付:

| 表單 | `id` 清單(依 body 順序) | 重複 |
| --- | --- | --- |
| `task.yml` | `background`, `ac`, **`depends-on`**, `links` | 無 |
| `bug.yml` | `repro`, `ac`, **`depends-on`**, `links`, `defect-class` | 無 |

**聲明**:兩份表單各自內部 `id` 皆不重複(以 `collections.Counter` 實算,見上表),
且新欄位**不設 `render:`**。`id` 的 `depends-on` 只用到字母與 `-`,符合官方對 `id` 的字元限制
(逐字見上一節第三列)。跨檔同名(`ac`、`links`、`depends-on`)是刻意的:官方要求的是
「unique in the form definition」,範圍是單一表單。

### AC-4 — `config.yml` 的說明同步 ✅(條件成立,已加)

條件**成立**,不是「沒提到就不改」:`config.yml` 原本第 1–2 行的檔頭註解就在講兩套表單的欄位
(「task / bug 兩套表單的 AC 欄必填 Given/When/Then」)。所以那一句說明是必加的。改後的檔頭:

```yaml
# issue 入口(asp-ng 消費端):task / bug 兩套表單的 AC 欄必填 Given/When/Then;
# 兩套表單的「依賴(depends-on)」欄非必填,有先後關係時每個依賴寫一行 `depends-on: #N`
# (N 是本 repo 的票號)——runtime 只讀得懂整行這個形狀,寫散文「依賴 #69」不會被認得。
# 想法階段的票走 blank issue,triage 時補 AC 或歸檔;blank issue 沒有表單欄位,
# 依賴那一行要自己寫進票文(格式同上)。
```

同檔還有 `blank_issues_enabled: true` 與把想法階段的票導去 blank issue 的 `contact_links`——
那條路徑走不到新欄位,依賴只能手寫。檔頭第 4–5 行交代了這件事,`contact_links[0].about`
也補了一句「有依賴請自己寫一行 depends-on: #N。」(該值因此加了引號:plain scalar 裡的 `: `
會讓 `yaml.safe_load` 丟 `ScannerError`,我寫壞過一次、已修)。這一條超出 AC-4 的字面
(它只要求「若提到欄位就同步一句」),做它是因為 #70 那類事故從 blank issue 會原樣再發生一次。
