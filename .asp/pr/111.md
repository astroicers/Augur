# docs(issue-template): depends-on 欄位說明補「不要加項目符號」

Closes #111

## 問題

#109 / PR #110 在兩份 issue 表單加了 `depends-on` 欄位。runtime 認依賴的正規式是
`^\s*depends-on:\s*#(\d+)`(不分大小寫、逐行比對;來源為 #109 票文對 asp-ng `launcher.py`
`_DEPENDS_ON` 的引述,本容器沒有 asp-ng 原始碼,仍屬**轉述**)。

多行 textarea 很自然會被當成清單填,而**項目符號會讓整行不命中**:使用者寫
`- depends-on: #69` 以為登記了依賴,runtime 視為沒有依賴照常派工,沒有任何紅燈——
這正是 #70 那起事故的形狀(票文寫「依賴 #69」,機器讀不到,在 #69 合併前就產出 PR #75)。
欄位 `description` 原本只寫了正面格式,沒有警告這件事。

本機實測(`re` 模組,正規式同上)哪些前綴會壞:

| 填法 | 命中 |
| --- | --- |
| `depends-on: #69` | ✅ |
| `   depends-on: #69`(純縮排空白) | ✅ |
| `\tdepends-on: #69`(tab) | ✅ |
| `DEPENDS-ON: #69` | ✅(IGNORECASE) |
| `- depends-on: #69` | ⛔ |
| `* depends-on: #69` | ⛔ |
| `+ depends-on: #69` | ⛔ |
| `1. depends-on: #69` | ⛔ |
| `> depends-on: #69` | ⛔ |
| `依賴 #69` | ⛔ |

所以警告句要列的不只票文舉的 `-`、`*`、`1.`,還有引用符 `>`(`>` 不是空白,整行不命中);
反過來**純縮排不會壞**(正規式前綴是 `\s*`),這點寫明可以省掉使用者反向誤解。

## 做法

一句定稿、三份檔案**逐字同一串**(含標點與反引號):

```
不要在那一行前面加 `-`、`*`、`1.`、`>` 等項目符號或引用符號——整行必須以 `depends-on:` 起頭,加了會靜默不命中、runtime 當成沒有依賴照常派工;純縮排的空白不影響。
```

- `.github/ISSUE_TEMPLATE/task.yml`、`bug.yml`:接在 `depends-on` 欄 `description`
  折疊純量(`>-`)的既有兩行之後,成為第三行。
- `.github/ISSUE_TEMPLATE/config.yml`:接在檔頭依賴欄說明之後,成為一行註解。

定稿句在三份檔案裡都是**單一整行**,刻意不折行:YAML `>-` 折疊會把換行接成空格,
拆行就會讓表單裡的字串與 `config.yml` 的註解差一個空白、不再逐字相同。因此這一行較長。

另外訂正 `.asp/pr/109.md` 的一處錯誤引用(AC-4)。

`src/`、`.config/`、`package.json`、lockfile 一行未動;零新增測試(純表單文字,無程式邏輯)。

## AC 逐條對照

### AC-1 — 兩份表單的 `description` 多了那一句、且逐字一致 ✅

兩份的 `depends-on` 欄 `description` 各加同一句。折疊後的完整字串(兩份相同):

```
每個依賴一行 `depends-on: #N`(N 是本 repo 的票號);沒有依賴就留空。 runtime 只認「整行以 depends-on: #N 開頭」的那一行:寫成「依賴 #69」或只寫 `#69` 不會被認得。 不要在那一行前面加 `-`、`*`、`1.`、`>` 等項目符號或引用符號——整行必須以 `depends-on:` 起頭,加了會靜默不命中、runtime 當成沒有依賴照常派工;純縮排的空白不影響。
```

逐字一致不是靠肉眼比 diff,是 `yaml.safe_load` 後比對字串:

```
desc task==bug (逐字): True
```

措辭對票文的 Then 做了兩處**語意不變的加強**(票文明文授權「措辭可調,語意不變」):
多列了引用符 `>`,並補一句「純縮排的空白不影響」。兩者都有上表的本機實測支撐。

### AC-2 — one-liner exit 0、`id` 仍唯一、`placeholder` 不變 ✅

```
$ python3 -c 'import yaml,sys; [yaml.safe_load(open(f)) for f in sys.argv[1:]]' \
    .github/ISSUE_TEMPLATE/task.yml .github/ISSUE_TEMPLATE/bug.yml
$ echo $?
0
```

連 `config.yml` 一起餵也是 0。`id` 與 `placeholder`(以 `collections.Counter` 實算):

| 表單 | `id` 清單(依 body 順序) | 重複 | `depends-on` 的 `placeholder` |
| --- | --- | --- | --- |
| `task.yml` | `background`, `ac`, `depends-on`, `links` | 無 | `depends-on: #69`(未動) |
| `bug.yml` | `repro`, `ac`, `depends-on`, `links`, `defect-class` | 無 | `depends-on: #69`(未動) |

本次只動 `description` 一個鍵,`id`/`label`/`placeholder`/`type`/`validations` 都沒碰;
diff 的三個 YAML hunk 皆為純新增一行,可逐行覆核。

### AC-3 — `config.yml` 的依賴欄說明同一句同形 ✅

不是 same-family 而是**逐字同一串**(`SENT in config.yml` → True)。該說明原本就存在
(#109 AC-4 的條件式產出在 PR #110 確實落地了),所以是在既有說明後補一行註解,不是新增整段。

### AC-4 — `.asp/pr/109.md` 的錯誤引用已訂正 ✅

原文那半句是「`:134` 就是「散落-3」那一條(含五欄格式),`:111` 是 V-4 KittenTTS 的條目,
那條引用規則在 `:67`」。以**當下 head** 覆核 `docs/ROADMAP.md`,票文的更正是對的:
`:111` 是〈V-2　https 與 Frontend Sandbox 下的外部語音〉、V-4 KittenTTS 在 `:113`、
散落-3 在 `:134`、引用規則在 `:67`。

但沒有照票文把數字改成 `:113` ——改成另一組會再漂的數字只是把同一個缺陷往後推。
`docs/ROADMAP.md`〈未完成項目〉檔頭自己明訂「引用一律用檔案路徑與章節名、commit 用標題」,
理由就是「原檔的行號錨點漂移到 22 處解析到錯的內容」,而那整段文字的結論正是「行號會漂」。
所以改寫成不含行號、用章節名與條目代號指涉,並把該規則的逐字引用補進括號裡。
AC-4 的 Then 是「已刪除**或**改為正確行號」,取前者。

被訂正的只有這一處;同段保留的「`docs/ROADMAP.md:134`」是**轉述留言原文**的引號內容,
不是本文件自己的引用,動它會改掉被引述的話。
