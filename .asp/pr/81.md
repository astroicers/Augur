# feat(feed): 清單列標出抖動／靜音時段未念;別名設定寫錯時在編輯模式提示

Closes #81

## 問題

兩件事已經在資料層算好了,畫面上卻看不到:

1. 導播回傳的每一則 item 帶有 `suppressed`(`'flapping'`／`'quiet'`,#63、#64),
   但清單列沒有顯示 —— 使用者看到一列句子躺在那裡,卻聽不到聲音,也看不出「這句為什麼沒念」。
   從畫面上分不出「它沒念」與「我沒聽到」。
2. 別名設定寫錯的項目由 `describeSkippedAliases`(#51)回報,但**沒有任何 UI 使用它** ——
   `P1-critical`(少打一個 `=`)這種錯會靜默失效:面板毫無反應,而使用者找不到哪裡錯。

## 做法

新增 `src/feed/feedNotices.ts`(**純函式**,107 行),只決定**文字**;元件那一側是三處接線。

| 匯出 | 做什麼 |
| --- | --- |
| `suppressedMark(reason, lang)` | 一列上的標記:`{ label, title }`。兩種原因 × 兩種語言共四組,label 進畫面、title 是滑過去才看到的完整原因 |
| `skippedAliasNotice(skipped, lang)` | 編輯模式那一行提示;**轉手** `describeSkippedAliases` 的輸出(AC-2 指名用它),沒有被略過的項目回 `null` |
| `isPanelEditor(app)`／`PANEL_EDITOR_APP` | 編輯模式的判定:`data.request?.app === CoreApp.PanelEditor`。缺席時回 `false` |

元件那一側(`MascotPanel.tsx`)只有三處:

```tsx
// 1. 導播算好的原因原樣轉手進 feed（元件不重算：那條閘門只能有一個住處）
suppressed: item.suppressed,

// 2. 清單列：值就是原因字串；沒有 suppressed 的列整個屬性都不渲染
<div … data-origin={r.origin} data-suppressed={r.suppressed}>
  <span className={styles.when}>{r.when}</span>
  {mark && <span className={styles.suppressedMark} title={mark.title}>{mark.label}</span>}
  <span>{r.text}</span>
</div>

// 3. 編輯模式才算、也才顯示的那一行
const aliasNotice = isPanelEditor(data.request?.app)
  ? skippedAliasNotice(parseSeverityAliases(severityAliasSpec).skipped, alertLang)
  : null;
```

### `SuppressReason` 從導播搬到 `core/types.ts`(本票唯一動到既有介面的地方)

清單列要標出原因,於是 `feed/feedRows.ts` 也得認得這個型別。而**兩邊都有一支既有測試
逐項比對自己的 import 清單**(`feedRows.test.ts` 的 `不 import React、不碰 DOM` 與
`BroadcastDirector.test.ts` 的 `AC-1：導播不 import react、不碰 DOM`),從 feed 去
import 導播會讓前者變紅、把它 re-export 出來會讓後者變紅。

處置是把定義移到那條唯一的抽象邊界旁邊(`src/core/types.ts`),兩邊就都只讀 `core/types`:

```ts
// BroadcastDirector.ts —— import 清單的字串一字未變（同一個來源、同一個位置）
import type { AlertLang, BroadcastPlan, ParsedAlert, SuppressReason } from '../core/types';
export type { SuppressReason };   // 沒有 from 子句，既有的 import 清單斷言照樣綠
```

既有呼叫端(`import type { SuppressReason } from '…/BroadcastDirector'`)一字不必改,
兩支 import 清單斷言**都沒有放寬**,全程綠。

### `data-suppressed` 的值釘死為原因字串(回應票上留言 (b))

`data-suppressed="flapping"`／`="quiet"`,**不是** `="true"`。留言指出的風險是真的:
值是 `true` 的話,AC-4 要的「兩種標記」就只能靠中文字面值分辨,`alertLang` 一改測試就碎。
釘死原因字串之後,`suppressedMarks(view)` 這個測試工具回的是 `['quiet']`／`['flapping']`,
與顯示文字無關。沒有 `suppressed` 的列傳進去的是 `undefined`,React 於是整個屬性都不渲染。

### 中英文都進 AC,`describeSkippedAliases` 多一個 `lang`(回應票上留言 (c))

票文只給了中文例句,AC-3 卻要求「中英文跟著 `alertLang`」。本票把四個標記字串
(zh／en × flapping／quiet)**逐字釘進測試**,編輯模式那一行也兩種語言各一支。

別名提示那一句原本只有中文。選擇是**給 `describeSkippedAliases` 加一個 `lang` 參數**
(預設 `'zh'` ＝ #81 之前的輸出逐字相同),而不是在 `feedNotices.ts` 另組一句英文:
中英兩套文字只有一個住處,日後多一種略過原因不會只補到其中一邊。

`lang` 的型別是本檔新開的 `SkippedAliasLang`,**刻意不 import `core/types` 的 `AlertLang`**
——`severityAliases.ts` 的檔頭第一句就是「純函式、零相依(只 import `severity.ts`)」,
而那條不變量有一支既有測試逐項比對 import 清單。代價(兩個聯集要一致)由
`feedNotices.test.ts` 的**雙向可指派**斷言在 typecheck 時擋住,不是靠人記得。

### 編輯模式的判定寫明,而且補了正向斷言(回應票上留言 (a))

留言這一點最要緊:panel plugin 拿不到現成的 `isEditing` 布林,實務上的路子是
`data.request?.app`(`CoreApp.PanelEditor`),而這個 repo 自己就記錄過
**`data.request` 在真實部署裡會缺**(12.3.x 的 dashboard uid 那次)。若只驗「觀看模式不顯示」,
那條 AC 在「提示永遠不顯示」的實作下照樣全綠 —— 一條只驗得到否定面的 AC。

處置三件:

1. **判定來源寫進程式與文件**:`isPanelEditor(data.request?.app)`,常數 `PANEL_EDITOR_APP`。
2. **正向斷言**:`#81 AC-2：編輯模式下列出被略過的別名設定與原因` 直接斷言那一行**在**,
   而且內容含兩個項目與各自的原因;觀看模式那一支用**同一份 props 只改 `app`** 做對照組,
   提示必須重新出現(否則它也只驗得到否定面)。
3. **退化方向誠實記下來並釘住**:`request` 缺席時 `isPanelEditor` 回 `false` → 不顯示。
   有一支測試(`#81 AC-2：\`data.request\` 整個缺席時不顯示`)釘住這件事。
   方向是刻意的 —— 牆面螢幕上多一行設定錯誤的提示,比編輯者少看到一行糟得多;
   編輯者打開編輯面板就會再看一眼,而值班的人被干擾時無從判斷那一行該不該理。
   `src/README.md` 把這個限制寫出來。

### 版面:標記不折行、不破版(回應票上留言 (d))

標記**自己一個 class**(`styles.suppressedMark`),不動每一列共用的 `styles.line` ——
AC-1 要求沒有 `suppressed` 的列「畫面與現在逐字相同」,改共用的 class 就不算。
`flex-shrink: 0` ＋ `white-space: nowrap`:窄面板(`width < 320` 改成上下堆疊)時標記
不折成兩行、也不被句子擠掉;句子本身是 flex item 裡的文字,照樣自己換行,
所以擠的時候是句子多佔幾行而不是標記破版。

誠實記:**jsdom 沒有版面計算**,所以那一支窄面板測試驗得到的是「窄面板不走另一條
渲染路徑」(標記仍在那一列裡、仍帶 `data-suppressed`),測試名稱就照這個寫。
「不折行」本身只有 CSS 保證,沒有測試釘得到(容器內無 docker,沒開過真的瀏覽器)。

### 兩個票文沒說、但一定得選一個的決定

- **只有本分頁的列可能帶標記。** 紀錄列來自 Grafana 自己的狀態歷史(ADR-006),
  那份資料記的是「狀態變化」而不是「這個分頁念了沒有」—— 抑制是本分頁的導播當下的決定,
  紀錄裡沒有、也不該猜。後果是:同一件事若在合併窗內也進了紀錄,畫面上留的是紀錄列,
  標記跟著本分頁那一列一起消失。有一支測試釘住這個行為,`src/README.md` 誠實寫出來。
- **ADR-007 的每瀏覽器靜音不標。** 那是觀看者自己按的開關(按鈕本身已經寫著「靜音中」),
  而標記報的是「導播自己決定、使用者看不到的原因」。導播的 `BroadcastItem.suppressed`
  本來就是這個語意,這裡只是沒有擴張它。
- **CSV 匯出的三欄不動**(#80 的格式契約不變)。標記是畫面上的事;要不要多一欄「念了沒」
  是另一張票的範圍,本票不擅自改已經對外講過的檔案格式。
