# feat(panel): 跨 panel 偵測降級後可恢復(ROADMAP 附錄-7)

Closes #36

## 問題

`src/components/MascotPanel.tsx` 的互動層只在 mount 時呼叫一次 `probeDashboardDom`,
把當下那張 DOM 快照變成**永久判決**:mount 瞬間只看得到自己(其他 panel 還沒 render 完、
使用者等一下才展開收起來的 row、或 panel 剛被加進一個原本只有它自己的 dashboard),
就永遠停在「限本 panel」,之後 dashboard 上出現多少 panel 都不會再看一眼。

同一段還有兩顆連動的地雷:
- `target` 是 `const`,升回必然要重綁 —— 只改 chip 不改 target 就會變成「畫面在說謊」
  (chip 寫全頁追蹤、事件卻仍只來自自己容器),而那個 chip 正是 G-ADR004-4 的目視證據。
- `onClick` 讀的是閉包裡的 `dom`。就算 target 換了,`panelAt` 仍是 mount 當下那份
  (降級版固定回 `null`),於是「全頁追蹤」底下點別的 panel 顯示的還是「已降級」。

`src/dom/dashboardPanels.ts` 當時沒有任何單元測試。

## 做法

### `src/dom/dashboardPanels.ts`:新增 `watchDashboardDom`(重試政策住在這裡)

`probeDashboardDom` 一字未改 —— 它仍是純粹的「照一張快照」。重試包在新的一層:

```
watchDashboardDom(self, onUpgrade, opts?) -> { current(), recheck(), retriesLeft(), stop() }
```

兩條觸發來源刻意分開,因為補的洞不同:

| 來源 | 界限 | 補的情況 |
| --- | --- | --- |
| 計時器重試 | `DOM_PROBE_RETRY_LIMIT = 4` 次 × `DOM_PROBE_RETRY_INTERVAL_MS = 1500ms` = **總窗 6 秒** | 使用者完全不動滑鼠 |
| `recheck()`(呼叫端在 pointermove 裡呼叫) | 節流 `DOM_PROBE_RECHECK_MIN_INTERVAL_MS = 1000ms`,不設次數上限 | 6 秒之後才出現其他 panel(例:使用者 1 分鐘後才展開 row) |

計時器有界的理由:超過 6 秒還看不到別人,絕大多數是真的只有一個 panel 或 sandbox 開著 ——
那不是暫時狀態,無限輪詢只是每隔幾秒燒一次 `querySelectorAll` 卻永遠得到同一個答案。
`recheck()` 不設次數上限的理由:它只在使用者真的在動游標時才跑,成本上界由節流窗(每秒最多
一次 `querySelectorAll`)而不是次數決定;若它也吃計時器的額度,「動一下滑鼠就升回」這條
在 panel 開著一小時後就會失效,而那正是這張票要修的症狀。

**只升不降**:升回後 watcher 自己停掉,`onUpgrade` 至多呼叫一次。偵測到別人之後又「看不到」
只可能是 panel 被移除,而那時 `panelAt` 自己就回 `null` —— 不值得為一個不會發生的狀態
付「降級要重綁 listener」的複雜度。還是降級時連 `reason` 都不換(`current()` 回同一個物件),
省掉一次沒有意義的 re-render。

### `src/components/MascotPanel.tsx`:能力 → 顯示 + target 收斂成一個函式

```ts
const apply = (dom: DashboardDom) => {
  domRef.current = dom;                              // onClick 讀這裡(不再讀閉包)
  setScope({ cross: dom.crossPanel, reason: dom.reason });
  bind(dom.crossPanel ? document : host);            // 舊 target 解綁 + 新 target 綁上
};
const watcher = watchDashboardDom(host, apply);
apply(watcher.current());
```

AC-2 要防的「chip 與 target 不同步」在結構上就不可能了:兩件事只在 `apply()` 裡動,
而初次偵測與升回走的是**同一個** `apply`。`bind(next)` 記著目前綁在哪,同 target 直接早退;
卸載時 `bind(null)` —— 不是對 host/document 各 remove 一次,所以升回過的那次會從 document 解綁。

卸載清三樣:`watcher.stop()`(重試計時器)、`cancelAnimationFrame(raf)`、`bind(null)`(listener),
加上原本就有的 click 回饋計時器。`domRef.current = null` 照舊。

降級本身的語意沒變:全部差別仍然只有 `target` 是 `document` 還是 `host`,
其餘互動邏輯一行都沒動(視線計算、dead zone、click 回饋整段照搬)。

兩則 lease 留言(2/3、3/3)是排程雜訊,無 AC 內容。留言 1/3 的作者**不是** repo
collaborator,依簡報規則僅供參考;其兩點建議我的處置如下(照票文做,差異寫在這裡):

- **(a) 「有界」無法驗收,建議明訂重試上限與觸發來源** —— 採納,因為它與票文
  「有界的重試」同向且只是把它寫死:上限 = `DOM_PROBE_RETRY_LIMIT`(4)×

  的 `recheck()`,後者節流 1 秒),三個數字都是 export 的常數並由測試直接引用 ——
  「兩種實作都算過」的問題不存在:兩條來源各有一條測試,有界本身也有一條。
- **(b) 「本副本只有 25 條 it/test,AC-5 的 50 可能寫錯」** —— **不採納,票文是對的**。
  實測 `grep -c '^\s*\(it\|test\)(' src/components/__tests__/MascotPanel.test.tsx` 在本分支
  改動前 = **50**,與 `tools/asp-test.sh` 的註解(components/MascotPanel 50)一致;留言的 25
