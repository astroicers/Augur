# fix(feed): 別名提示改看網址上的 editPanel——Grafana 12 的編輯器不給 `app: 'panel-editor'`

Closes #100

## 問題

#81（PR #93）的別名提示只在編輯模式顯示，判定是 `MascotPanel.tsx` 裡的一行：

```ts
const aliasNotice = isPanelEditor(data.request?.app) ? skippedAliasNotice(…) : null;
```

v0.4.0 發版前在 Grafana 12.4.12 實測（`/d/rel030?editPanel=3`，把 `severityAliases` 填成
`P1=critical, bogus, sev9=nope`）：**提示沒有出現**。那個 panel 有 Prometheus query，
所以 `data.request` 是存在的 —— 可見 12.x 的編輯器傳進來的 `app` 不是 `'panel-editor'`。
淨結果是這一行在真實 Grafana 上**永遠不顯示**，寫錯的別名照樣靜默失效，
也就是 #81 整張票想擋的那件事。

## 做法

判定改成**兩個訊號取聯集**，並且保留 `data.request` 那道閘門（AC-3）：

```ts
// src/feed/feedNotices.ts（純模組，不碰 Grafana）
export function isPanelEditing(args: { app; hasRequest; editPanel; panelId }): boolean {
  if (!args.hasRequest) { return false; }                                   // AC-3，方向不變
  return isPanelEditor(args.app)                                            // 舊訊號，留著
      || isEditPanelParamFor(args.editPanel, args.panelId);                 // 新訊號
}

export function isEditPanelParamFor(editPanel: string | null | undefined, panelId: number) {
  return typeof editPanel === 'string' && /^\d+$/.test(editPanel) && Number(editPanel) === panelId;
}
```

舊訊號**沒有拿掉**：我們實測到的只有「它在 12.4.12 不成立」，沒有任何證據說它在別的版本
或別的進入路徑（例如新建 panel）也不成立。拿掉等於多冒一次險，而聯集的成本是零。

### 新訊號讀在哪一層（票上留言 (a)）

`locationService` 來自 `@grafana/runtime`，而 `src/feed/feedNotices.ts` 是純文字模組
（它自己的測試有一條掃原始碼的斷言在釘「只 import `../core/types` 與 `../core/severityAliases`」）。
把網址讀進那支會開本專案第一個 `jest.mock('@grafana/runtime')`，並讓純模組從此需要替身。
**採用留言的建議**：

- 讀網址的那兩行關在新的一支薄檔 `src/components/useEditPanelParam.ts`
  （理由與作法比照 `src/sources/rulesFetcher.ts` 的檔頭）；
- 純函式只收**已經讀好的字串**（`editPanel: string | null | undefined`）與 `panelId`；
- `src/__tests__/implementation-contract.test.ts` 新增一條契約測試，把
  「import `@grafana/runtime` 的生產碼」釘成**全等**的三支清單
  （`useEditPanelParam.ts`／`sources/rulesFetcher.ts`／`sources/historyFetcher.ts`）。
  用全等而不是「不得包含 feedNotices」：多一支薄檔是刻意決定，該在這裡被看見。

結果：**本 PR 沒有新增任何 `jest.mock('@grafana/runtime')`**，全 repo 仍然是零個。
jest 下 `locationService` 本來就接在 memory history 上（出處見下），測試用公開的
`locationService.replace('/d/rel030?editPanel=7')` 擺網址，驗到的是真的 `getSearch()`。

### 字串 vs 數字（票上留言 (b)）

**採用**。查詢參數是字串、`PanelProps.id` 是數字，`'7' === 3` 與 `'7' === 7` 都是 false —— 直接比
會讓提示在**自己的**編輯器裡也不出現，正是本票症狀換一個成因。`isEditPanelParamFor` 先
`/^\d+$/` 守門再 `Number()` 轉型；不用 `Number()` 當守門員是因為 `Number('')` 是 0、
`Number(' 7 ')` 是 7，`?editPanel=` 這種空值會在 `id === 0` 的 panel 上誤判成編輯中。
AC-4 第三支測試的輸入就是「同一個 id 的字串」（`editPanel=7`、`props().id === 7`）。

### 何時讀：訂閱，不是 render 期間讀一次（票上留言 (c)）

**採用，但走的是訂閱而不是補依據**。留言給了兩條路：補一條切換場景的測試，或在 PR 裡
交代「12.x 進編輯器會重掛 panel」的依據。後者我**交代不出來**——`@grafana/runtime` 13.1.0 的
型別與 `@grafana/plugin-e2e` 都沒有對重掛做出任何保證，寫上去就是推論，而 AC-1 明文禁止推論。
所以改成讓這件事**不需要假設**：`useEditPanelParam()` 訂閱
`locationService.getLocationObservable()`，重掛與否都正確。切進／切出各有一支測試
（hook 層與 `MascotPanel` 接線層各一），兩支都在**同一次掛載**內換網址。

### AC-1 要的出處（票上留言 (d)：寫明可接受的出處）

全部取自**容器內安裝好的套件**（worker 讀得到；不是 grafana/grafana 的原始碼）：

### 回歸落槌（mutation check）

把新訊號拿掉（`return isPanelEditor(args.app)` 單打）→ **3 支紅**；
把轉型比對換成裸 `===`（`editPanel === panelId`）→ **4 支紅**。兩個缺陷都抓得到。

## 範圍外的一行（主動宣告）

## 單元測試驗到哪一層、哪一層要靠實測

**單元測試驗得到**（容器內沒有 Grafana）：

1. 判定邏輯本身（聯集、轉型、`hasRequest` 閘門、`editPanel` 的字串邊界）——`feedNotices.test.ts` 純函式；
2. 「網址 → 字串」這一段走**真的** `locationService`（memory history，無替身）——`useEditPanelParam.test.tsx`；
3. 元件接線：同樣的網址 + 同樣的 props 真的渲染／不渲染 `[data-testid="alias-notice"]`，
   以及同一次掛載內換網址會跟著變 ——`MascotPanel.test.tsx` 的 `#100` 區塊。

**只能靠實測**（合併後請用 v0.4.0 那套隔離環境，Grafana 12.4.12）：

1. **真實編輯器的網址真的是 `/d/<uid>?editPanel=<id>`**，且 `locationService.getSearch()`
   在 panel plugin 的 render 期間讀得到它。上表第四列是官方 e2e 套件在對真實 Grafana 做的事，
   屬強證據但不是我們親眼在 12.4.12 的執行期驗過；jsdom 的 memory history 不能替代這一點。
   建議重跑票文那個案例：`/d/rel030?editPanel=3` + `severityAliases: 'P1=critical, bogus, sev9=nope'`
   → 應看到略過 2 項的提示。
2. **`app` 在 12.4.12 的實際值**。本 PR 不依賴它（聯集），但若實測印出它到底是什麼
   （`panel-edit`？`dashboard`？），下一張票可以決定要不要把字面值補進 `PANEL_EDITOR_APP` 旁邊。
3. **切進／切出編輯器時 Grafana 會不會重掛 panel**。訂閱的設計讓這件事不影響正確性，
   所以不必為它開票；順手確認一下「關掉編輯器那一行會消失」即可（值班牆的那一條）。
4. **`editPanel` 以外的編輯入口**：Scenes 的「編輯 dashboard → 選 panel」若用了不同的網址形狀，
   這個訊號對它不成立，會退回舊的 `app` 訊號（也就是維持現狀，不會變得更糟）。
