# feat(director): 抖動告警抑制——同一則在窗內反覆翻轉時先不念，穩定後念當下狀態

Closes #64

## 問題

閾值附近的告警會在 firing 與 resolved 之間來回翻，而現在每翻一次就念一次：
「偵測到告警……」「已恢復……」「偵測到告警……」。吉祥物因此變成噪音，值班的人學會不聽它。

去重（`src/core/dedup.ts`）擋不住這件事：它管的是「同一則**持續燒**時多久重播一次」，
而翻轉的每一次都是**狀態真的變了**，照它的語意本來就該放行（resolved 綁狀態還會把 key 刪掉）。
所以本票在導播（#58）加的是**另一道閘門**，不是把防洪窗調大。

⚠️ 命名：`src/avatar/flap.ts` 是**嘴型開合**，與本票無關。本票的模組、選項與測試一律 `flapping`／「抖動」。

## 做法

兩個新 panel 選項 + 導播裡一道閘門 + 一組純函式與一個以注入時鐘驅動的狀態機。

| 新增 | 做什麼 |
| --- | --- |
| `flappingThreshold`（數字，預設 `0`） | 窗內翻幾次算抖動。`0`／留空 = 關閉 |
| `flappingWindowMin`（數字，預設 `10`） | 窗長（分），同時是「穩定多久就解除抑制」的長度 |
| `parseFlapping(threshold, windowMin)` | 兩個原值 → `{ config, problem }`。純函式、不拋例外 |
| `describeFlapping(problem)` | 設定無效的原因講成一句話（比照 `describeQuietHours`） |
| `createFlappingTracker({ now })` | 狀態機：`observe()`／`release()`／`reset()`，時鐘注入 |
| `BroadcastItem.suppressed` | `'flapping'`／`'quiet'` —— 這一則沒交付的原因（AC-2） |

管線（`evaluate()`，粗體是本票新增）：

```
過濾（門檻＋別名）→ 防洪（dedup）→ 組句 → items
  ├ **解除抑制的補念**（排在這一輪最前面，不經 dedup 的放行判斷）
  → **抖動抑制？ 標 suppressed:'flapping'，不進交付候選**     ← 逐則，先判這個
  → 排程靜音時段內且破不了靜音？ 標 suppressed:'quiet'        ← 逐則
  → 沒有播報器／每瀏覽器靜音（ADR-007）？ 整輪都不交付        ← 整輪的開關
  → 其餘照時間順序交給播報器
```

三個位置都是刻意的，各有測試釘住：

- **在嚴重度門檻之後**：被門檻擋下的告警連 `observe()` 都看不到 → 不計入翻轉次數（AC-5 第一項）。
  理由與「門檻擋下的不進 dedup」同一條：一則從來不該出聲的告警不該讓另一則閉嘴。
- **在 dedup 之後**：看到的就是「若沒有抖動抑制、這一輪真的會念出來的那幾則」，
  翻轉次數於是與播出去的句數一致。dedup 吞掉的是「持續燒的重播」，那不是翻轉（狀態沒變），
  所以這個順序不會漏算任何一次翻轉。
- **在靜音閘門之前**：兩者同時成立時 `'flapping'` 為準（collaborator 留言的第一件事）。

**解除**是三道閘門裡唯一會「多念一句」的，而那一句不走 `dedup.shouldSpeak()`：

抑制期間的每一次翻轉都照常經過 dedup（與 #63 的靜音時段同一條理由 —— 不進 dedup 的話，
等它恢復時會冒出一句「已恢復」而使用者從沒聽過它燒起來），所以 dedup 手上記的正是
「最後那個狀態播過了」。而預設 `repeatFiringMin: 0` → 防洪窗是 `Infinity` → `t - last < Infinity`
恆真 → 想補念 firing 必定被擋下（`core/dedup.ts` 的 `forget()` 註解記著同一個坑）。
所以解除時由導播自己把 dedup 的狀態對回實際狀態：先 `forget()`（= 沒播過），
firing 再借 `shouldSpeak()` 的副作用重新記成「剛剛播過」；resolved 的對應狀態就是「什麼都不記」。
補念照樣過嚴重度門檻（`resolved` 不受門檻影響，與主迴圈同一條規則）與靜音閘門。

元件這一側是**純接線**：`options.flappingThreshold ?? 0` 與 `options.flappingWindowMin ?? 0`
原樣帶進 `DirectorSettings`，`MascotPanel.tsx` 沒有任何抖動判斷、也沒有自己的一份計數狀態
（那會把 #58 剛拆掉的東西搬回元件）。相依陣列不含這兩個，與 `repeatFiringMin`／`quietHours`
同一條理由（既有的 `eslint-disable` 註解已更新成「這六個」）。

### 取捨一：**達到門檻的那一次仍然念出來**

AC-2 的字面是「翻轉次數**達到** `flappingThreshold`，Then **之後的**翻轉不交給播報器」，
所以實作照字面做：門檻 4 的意思是「第 4 次翻轉是最後一次出聲，第 5 次起不念」。
「達標那一次就閉嘴」也讀得通，但那是「達到門檻**的**翻轉不交付」，不是票文寫的「之後的」。
依契約「判讀有疑義時照票文做」選了字面那一邊，並把它寫進選項說明、`src/README.md`、
`docs/ARCHITECTURE.md` 與測試名（`AC-4：剛好達到門檻的那一次照常交付，之後的翻轉才不交付`）。
若主管層要另一邊：把 `observe()` 裡的門檻判斷移到 `if (held.suppressed)` 之前（一次 3 行的位移），
`AC-4：剛好達到門檻…` 與 `#64 AC-2：達到門檻之後的翻轉…` 兩支會紅在該紅的地方。

### 取捨二：AC-3 的內部牴觸 —— 採「解除當下就念」

AC-3 中段寫「解除後的**第一次狀態變化**照常播報」，末段寫「不得因為抑制期間的翻轉而遺漏
『最後其實已經恢復』或『最後仍在燒』」。兩句對不起來：若抑制期間翻完、最後穩定在 resolved
滿窗而解除，之後**再也沒有狀態變化**（resolved 的 episode 不會再有事件），照中段做就永遠不念
那句恢復 —— 正是末段禁止的事。

實作取**末段＋AC-5 第二項**：解除時若當下狀態與抑制前最後播報的狀態不同，**立刻**播報當下狀態，
不等下一次變化；相同就不念（避免多一句重複的話）。AC-5 第二項「抑制解除了、卻被 dedup 擋住而
永遠不念當下狀態」只有在「解除當下就念」的讀法下才講得通 —— 它要擋的就是這一句被 dedup 吃掉。
中段那句在實作裡同樣成立（解除後的下一次狀態變化照常播報，有測試）。

### 取捨三：窗長 0／負數／非數字 = **整個抖動抑制關閉**（AC-1 沒定義的那一塊）

比照 #63 AC-4 的「解析失敗視同沒設定並可回報原因」：`parseFlapping` 回
`{ config: null, problem }`，三種原因 `'off'`（門檻 0／留空，**不是錯誤**）、
`'bad-threshold'`（負數／NaN／Infinity／非數字）、`'bad-minutes'`（窗長不是大於 0 的數字），
行為一律相同（關閉），只是 `describeFlapping()` 能講出原因。

窗長 0 **不另立語意**：它會讓「穩定滿窗」在定義上立刻成立（抑制進得去、下一輪就解除），
使用者看到的是「設了卻沒用，還多一句補念」。兩種讀法都說得通的設定不猜。
門檻的小數往上取整（`2.5` → `3`）：往上是保守的那一側（寧可多翻一次才抑制）。

### 取捨四：純函式住在 `BroadcastDirector.ts`，沒有開 `src/core/flapping.ts`

票文〈範圍〉允許「`src/core/` 下新的純模組」，本票沒有開 —— 與 #63 同一個機械理由：
#58 留下的既有測試 `AC-1：導播不 import react、不碰 DOM` **逐項比對導播的 import 清單**
（`expect(sources).toEqual([…六項…])`），多一個 `import … from '../core/flapping'` 就會讓那支
既有測試變紅，而本票 AC-1 要的正是「既有測試一行不改且全綠」。
兩者兼得只有兩條路：拆檔並改那支測試一行（違反 AC-1），或把它放進導播（不動既有測試）。
檔內那一段註解把理由寫下來了，**日後要拆成 `core/` 模組的改動就是那一行 import 清單加一次 `git mv`**。

順帶一件事：`'bad-minutes'` 這個名字不是隨便取的 —— 那支既有測試還斷言導播的程式碼
（去掉註解後）不含 `/\bwindow\b/`，而 `'bad-window'` 裡的 `-` 是 word boundary，會踩中它。

### 取捨五：`suppressed` 不標每瀏覽器靜音

`'flapping'` 與 `'quiet'` 報的是「導播自己決定、呼叫端看不到的原因」。ADR-007 那顆靜音鈕是
呼叫端自己持有的開關（它按的、它存的），而且那一刻整輪都沒有交付、`pending` 為 `null`
已經說完了。`'quiet'` 的標記**不受靜音鈕影響**（標的是「落在時段內且這一則破不了靜音」這個事實），
所以 `isQuietAt` 的判斷與標記移到了 `muted()` 早退之前 —— **交付**仍然全部排在那個早退之後，
`quietAllowCritical` 在結構上依然蓋不過觀看者自己按下的開關（#63 AC-6 的測試照樣綠）。
