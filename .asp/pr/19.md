# fix(core): severity 缺值或非字串時 rankOf/meetsMin 不再拋例外

Closes #19

## 問題

`rankOf(severity)` 直接呼叫 `severity.trim()`。型別標成 `string`,但告警資料來自 Grafana
的面板資料,實際上可能缺這個欄位(`undefined`)、是 `null`,或不是字串——這時 `rankOf`
拋 `TypeError`,連帶 `meetsMin` 也拋,`MascotPanel` 的過濾迴圈(`src/components/MascotPanel.tsx:642`)
整條斷掉,面板的播報流程中斷。

## 做法

`src/core/severity.ts` 三個 export 的入參一律放寬成 `unknown`,改以 runtime 檢查為準:

- 新增私有 `normalize(severity)`:`typeof === 'string'` 才 `trim().toLowerCase()`,否則回 `null`。
- `rankOf` / `isKnownSeverity` / `meetsMin` 都走 `normalize`,非字串即視為「查不到」。
- 排名表 `RANK` 從物件字面值換成 `Map`。這不是風格偏好:物件查表會連 `Object.prototype`
  一起查到,舊實作的 `rankOf('toString')` 會回傳一個 function(而非 0)、
  `isKnownSeverity('constructor')` 會回 `true`。這與 AC-1/AC-3 要求的「未知值回 0 / 回 false」
  直接相衝,所以一併修掉,並以測試釘住(`__proto__`、`constructor`、`hasOwnProperty`、`toString`)。
  用 `Map`(ES2015)而非 `Object.hasOwn`(ES2022)是因為 `.config/tsconfig.json` 的 `target` 是 es2018。

行為面只有一處放寬:`min` 若是非字串(例如 `null`、數字),視為「沒設門檻」→ 全部放行,
與 `min === ''`/`undefined` 的既有語義一致(最不意外)。既有通過的輸入,結果一字未改。

## 判讀說明(票上留言)

- **留言 1/2(collaborator,暫停/解除派工)**:流程排程事項,不含 AC,無對應程式碼改動。
- **留言 4(collaborator,人工套用 milestone P7)**:標籤/排程事項,不含 AC。
- **留言 3(`asp-ng-supervisor-legacy[bot]`,非 collaborator → 僅供參考)**:兩點建議都處理了,
  但依「有疑義時照票文做」:
  - (a) **AC-2 在 `min` 自身是 `unknown` 時的邊界**。確實,`unknown` 的排名是 0,`0 >= 0` 會放行,
    票文那句「低於任何已知門檻即不放行」字面上在此不成立。此處**照既有行為裁定為放行**,理由:
    (1) AC-4 要求既有行為照舊,舊實作在 `min='unknown'` 時就是全部放行;
    (2) `unknown` 是排名底線,拿底線當門檻在語義上等同「不過濾」,若改成不放行,
    `meetsMin('unknown', 'unknown')` 與 `meetsMin('critical', 'unknown')` 都會變 `false`,
    反而比拋例外更難預期;
    (3) 本票是防禦性修補,不是門檻語義重構。此裁定已在 `meetsMin` 的 doc comment 與
    測試 `meetsMin: 門檻為 unknown 是排名底線,等同不過濾` 中寫明釘住。
    若產品端其實想要「`min='unknown'` 代表排除缺值告警」,那是另一張票(需同時定義
    `unknown` 門檻與空門檻的差異),本票不自行擴張。
  - (b) **`npm run typecheck` 綠、呼叫點不需改動**:已自驗,見上方「額外自驗」。
