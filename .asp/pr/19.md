# fix(core): severity 缺值或非字串時 rankOf/meetsMin 不再拋例外

Closes #19

## 問題

`rankOf(severity)` 直接呼叫 `severity.trim()`。型別標成 `string`,但告警資料來自 Grafana
的面板資料,實際上可能缺這個欄位(`undefined`)、是 `null`,或不是字串——這時 `rankOf`
拋 `TypeError`,連帶 `meetsMin` 也拋,`MascotPanel` 的過濾迴圈(`src/components/MascotPanel.tsx:642`)
整條斷掉,面板的播報流程中斷。

## 做法

`src/core/severity.ts` 三個 export 的入參一律放寬成 `unknown`,改以 runtime 檢查為準:

- 新增私有 `normalize(severity)`:`typeof === 'string'` 才 `trim().toLowerCase()`,否則回 `null`。
- `rankOf` / `isKnownSeverity` / `meetsMin` 都走 `normalize`,非字串即視為「查不到」。
- 排名表 `RANK` 從物件字面值換成 `Map`。這不是風格偏好:物件查表會連 `Object.prototype`
  一起查到,舊實作的 `rankOf('toString')` 會回傳一個 function(而非 0)、
  `isKnownSeverity('constructor')` 會回 `true`。這與 AC-1/AC-3 要求的「未知值回 0 / 回 false」
  直接相衝,所以一併修掉,並以測試釘住(`__proto__`、`constructor`、`hasOwnProperty`、`toString`)。
  用 `Map`(ES2015)而非 `Object.hasOwn`(ES2022)是因為 `.config/tsconfig.json` 的 `target` 是 es2018。

行為面只有一處放寬:`min` 若是非字串(例如 `null`、數字),視為「沒設門檻」→ 全部放行,
與 `min === ''`/`undefined` 的既有語義一致(最不意外)。
**先前能跑的輸入(字串)結果一字未改**;先前不能跑的輸入(非字串)舊行為是拋例外,無可回歸的語義。

## gate 失敗診斷(attempt 1 / 2 / 3 皆記 `failed: gate`)

**先更正我前一趟寫在本檔的診斷。** 上一趟我認為成因是「判決時點早於產出 commit」
(attempt 1/2 的判決都比該趟 commit 早約一分鐘),並據此把工作順序改成「先 commit 再驗」。
**attempt 3 證否了這個說法**:

| --- | --- | --- | --- | --- |
| 1(留言 5→6) | 07:55:38 | 07:57:49 | `e92112d` 07:58:32 | 產出未 commit |
| 2(留言 7→8) | 08:03:02 | 08:13:48 | `65c2107` 08:14:50 | 產出未 commit |
| 3(留言 9→10) | 08:18:55 | **08:28:15** | `b694961` **08:24:15** | **5 筆 commit 全在、`git status` 乾淨** |

attempt 3 的產出在判決前 **3 分 50 秒**就已全部 commit 完畢、工作樹乾淨、
`.asp/pr/19.md` 在樹上,仍然 `failed: gate`。前兩趟的時間差是巧合(每趟工作節奏相近),
不是成因。三趟也都沒跑到原始 deadline(08:43:00 / 08:50:08 / 09:06:08),故亦非逾時。

**三趟唯一的不變量是 gitleaks 這支 blocker 在本容器無法執行。**
`asp-gate.yaml`(gate 的單一事實源,本 repo 已納管)把 gate 層定義成**恰好兩道**:

```yaml
- id: gitleaks        # tool: gitleaks, severity: blocker, requires: [.asp/gitleaks.toml]
- id: commit-format   # tool: builtin-regex, severity: blocker
```

且檔內註解明寫「型別、測試、建置、e2e 由本 repo 既有的 `.github/workflows/ci.yml` 承擔;
這裡只放 asp 這一側要的兩道關:密鑰與 commit 訊息」。也就是說**沒有第三道可能是我沒做到的**:
`commit-format` 三趟都綠(非 PR 與 `GITHUB_BASE_REF=main` 兩種情境都實測),
剩下的只有 gitleaks。帶 `ASP_GATE_MARKERS` 跑(代發路徑讀的就是這些標記,見 `.asp/gate.sh:48`
「代發路徑據此答出『哪一支紅』」),本趟 HEAD 實測輸出:

```
asp:gate-check id=gitleaks sev=blocker rc=1 status=missing
asp:gate-check id=commit-format sev=blocker rc=0 status=ok
```

`rc=1` 來自 `run_check` 的缺工具分支 `_mark "$id" "$sev" 1 missing`。腳本本身在
預設模式 `exit 0`(結論行「gate 通過但不完整」),但**逐支標記上 gitleaks 是 rc=1**;
而 `ASP_GATE_STRICT=1`(fail-closed,代發前的合理設定)時同一情形整份 **`exit 202`**
「未完整執行…不放行」。兩種讀法都會把這趟記成 gate 紅,且**與本票 diff 無關**。

### 為什麼 worker 補不了

| 事實 | 實測 |
| --- | --- |
| PATH 上沒有 gitleaks | `command -v gitleaks` → 無 |
| 容器內任何路徑都沒有 gitleaks 執行檔 | `find / -xdev -name 'gitleaks*' -type f` → 只有 `.asp/gitleaks.toml`(規則庫,非執行檔) |
| asp-ci 用的 vendoring 目錄不存在 | `~/.asp/tools/` → 不存在 |
| **容器沒有對外網路** | `registry.npmjs.org` DNS **不可解析**、`curl` http code `000`(探測對象刻意選非 GitHub;取 gitleaks 一律走 github.com releases,而出勤契約明寫不得存取 GitHub) |
| 容器沒有 `jq` | `command -v jq` → 無 |

`.asp/gate.sh` 自己的註解寫 gitleaks「vendoring 由 P2 base image 落地」,
而 `.github/workflows/asp-ci.yml` 是在 CI runner 裡現抓 v8.30.1(checksum-pinned)才有的 ——
worker base image 這一側還沒落地。無網路即無任何自補路徑。

**我不會做的兩件事,明說在此**:
1. 不改 `asp-gate.yaml` 把 gitleaks 降級成 warning 或加豁免——那是為了讓自己的出勤過關而
   削弱一道密鑰閘,且該檔是 asp-ng 側的單一事實源(改了還得在 asp-ng checkout 重新 `asp render`)。
2. 不手寫 `.asp-test-result.json`。它是閘門痕跡;`tools/asp-test.sh` 因缺 `jq` 在本容器
   第二行就 `exit 1`(實測印「asp-test: jq 不存在,無法產生測試痕跡」),偽造一份綠的比缺一份更糟
   ——該腳本檔頭第 11–14 行記的正是「殘留的綠痕跡蓋章放行一次 commit」這個失敗模式。
   代償是把該腳本涵蓋的每一道逐項手跑,清單與結果見〈測試〉。

## 附帶發現:commit-format 的型別清單漏了 `revert`,且 `git revert` 預設訊息必撞牆

`asp-gate.yaml` 的 commit-format 樣式是:

```
^(feat|fix|docs|refactor|test|chore|ci|perf|build|style)(\([A-Za-z0-9._/-]+\))?!?: .+
```

**`revert` 不在清單裡**,而 Conventional Commits 規範把它列為標準型別。影響有兩層:

1. 寫 `revert(scope): …` 會被判不合式。本票實測撞過一次:退回 MIN_TESTS 那筆原本寫
   `revert(asp): …`,PR 情境的 gate 直接 `exit 1`(blocker)。已改用 `chore(asp):` 通過。
2. 更要緊的是**`git revert` 的預設訊息是 `Revert "<原訊息>"`**——開頭既不是合法型別、
   也沒有 `: ` 分隔,所以**任何人在本 repo 上直接 `git revert` 再推上來,asp gate 一定紅**,
   而且訊息得手改才救得回來。回滾通常發生在出事的時候,那正是最不該多一道絆腳石的時刻。

另外值得注意:`commit-format` 在**非 PR 情境**只驗 `git log -1 --no-merges --first-parent`
(最近一筆),在 **PR 情境**(`GITHUB_BASE_REF` 有值)驗 `origin/<base>..HEAD` 範圍內
所有非 merge commit。所以「本機 gate 綠、PR gate 紅」是會發生的——本票的 `revert` 那筆
正是這樣被漏掉又被抓到的。worker 端的自驗因此**兩種情境都要跑**,本票已照此執行。

→ 處置屬 asp-ng(`asp-gate.yaml` 是其側的單一事實源,本 worker 不自行改動):
建議把 `revert` 加進型別清單,並額外容許 `Revert ".+"` 這個 forge/git 預設形式
(與 merge 訊息的豁免同理——那也是工具產生、不由人書寫的訊息)。
