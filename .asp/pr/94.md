# fix(feed): 抖動標記的說明別說太滿——解除抑制時狀態沒變就不補念

Closes #94

## 問題

#81（PR #93）在清單列的「抖動中，未念」標記上掛了一段 `title`
（`src/feed/feedNotices.ts` 的 `SUPPRESSED_TEXT`），末句把解除抑制寫成無條件會出聲：

- 中文：「維持同一個狀態滿一個窗之後，**會把當下狀態念出來**。」
- 英文："Once it holds one state for a full window, **the current state is spoken**."

導播的實際行為不是這樣。`BroadcastDirector.ts` 的 `createFlappingTracker`：

```ts
release(config) { … state.suppressed = false;
                  if (state.announced !== state.status) {        // ← 只有不同才進 pending
                    state.announced = state.status; pending.push(state.lastAlert); } … }
drain()        { … if (state.suppressed && state.announced !== state.status) { pending.push(…) } … }
```

`announced` 是「抑制前最後**念出去**的狀態」，抑制期間刻意不動（`observe()` 的早退）。
解除時當下狀態與它相同 → `pending` 是空的 → **一句都不出聲**，而且這是刻意的
（`flapping.test.ts` 的 `AC-3：解除時當下狀態與抑制前最後播報的相同 → 不補念`）。
原本的說明於是讓使用者等一句永遠不會來的話。

## 做法

只改那兩個字串（**導播一行未動**）：

| | 新文字 |
| --- | --- |
| `zh.flapping.title` 末段 | 「維持同一個狀態滿一個窗之後**解除抑制：當下狀態與上次念出去的不同才補念一句，一樣就不出聲**。」 |
| `en.flapping.title` 末段 | "**Suppression lifts** once it holds one state for a full window: the current state **is read out then only if it differs from the state announced last; if they match, nothing is said**." |

前半句（為什麼被擋下、#64）兩種語言都逐字不動 —— 那一段本來就是對的。

### 測試釘語意，不釘逐字句子

票上留言 (a) 建議把 zh/en 定稿寫進 AC-1、讓 AC-2 變成機械的逐字比對。
**沒有採用逐字斷言**（留言非 collaborator，僅供參考；票文 AC-1 要的是「寫明條件」）：
逐字比對會讓日後任何潤飾都變紅，而本票要擋的缺陷是「有沒有講條件」而不是「用哪一種措辭講」。
新測試改釘兩件可驗的事，正好對上留言 (b) 想要的可驗形式：

```ts
expect(zh).toContain('不同才補念');            expect(zh).not.toContain('會把當下狀態念出來');
expect(en).toContain('only if it differs');   expect(en).not.toContain('is spoken');
```

兩個 `not.toContain` 就是留言 (b) 的「文字不含無條件句式」——
AC-1 後半句「不再暗示一定會念」因此也落槌得出來，不必靠人主觀判斷。

### 「靜音時段，未念」那一則：檢查過，沒問題（留言 (c)）

同一支 `SUPPRESSED_TEXT` 的 quiet 文字是
「時段結束後**不會**補念。」／"It is **not** read out later when the window ends."
—— 方向與抖動那一則相反，是**否定**的保證，不會說太滿，所以本票不動它。對照程式碼：

- quiet 沒有 `release()`／`drain()` 這種補念路徑；被標 `suppressed: 'quiet'` 的那一則
  在閘門上 `continue` 掉就結束了（`evaluate()`），時段結束時沒有任何待補的佇列
  （`#63 AC-2：時段內的告警照樣經過 dedup —— 時段結束時不會一口氣補念出來`）。
- #84 的恢復側不影響這一則：`breaksQuiet()` 對 resolved 回 `brokeQuiet(fingerprint)`，
  破過靜音的那一則恢復時**是放行的**，因此根本不會被標 `quiet`、不會顯示這個標記。
  標記出現 ⇒ 這一則破不了靜音 ⇒ 它的恢復照舊不念（#84 AC-2）。

兩個已知的邊角，都不是「補念」、所以不改字：時段結束後若它仍在燒、且 dedup 的防洪窗到期，
那是**重播**（預設 `repeatFiringMin: 0` → 窗 `Infinity`，不會發生）；時段結束後才到的 resolved
是一次新的狀態變化，由當下的閘門決定，不是時段內那一句的補念。

### 範圍外的一行（主動宣告）

`src/README.md` 第 231 行的標記對照表**逐字轉抄**同一句英文說明。票文的〈範圍〉只寫
`feedNotices.ts` 與它的測試，但那一行留著就等於同一個缺陷還在文件裡（下一張票會再來一次），
所以一併改成與字串相同的新文字。**只有那一行，純文件、零行為**。
`docs/ARCHITECTURE.md`:292 與 `src/module.ts`:118（抖動選項的說明）另行檢查過：
ARCHITECTURE 本來就寫著「（與抑制前最後念出去的那個狀態不同時）」，是對的；
module.ts 那段是 #64 的選項說明、不在本票的交付物裡，未動。
