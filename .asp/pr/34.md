# refactor(sources): Grafana rules 回應的 panel 走訪三份合一

Closes #34

## 問題

同一段「`groups → rules`、再比對一次 `__dashboardUid__` / `__panelId__`」的走訪寫了三份:

| 函式 | 檔案 | 它真正要的東西 |
| --- | --- | --- |
| `parseRulesResponse` | `src/sources/panelAlerts.ts` | 正在燒的 instance → `RuleDetail[]` |
| `parseRuleTemplates` | `src/sources/history.ts` | **所有**規則的 rule-level 樣板 → `Map<string, RuleTemplate>` |
| `parseRulerConditions` | `src/sources/history.ts` | 規則 → 條件欄 → `Map<string, string>` |

三份的差別只在「從一條規則取什麼」;走訪與綁定比對一字不差。Grafana 改欄位名
(12.4.0 的 `dashboardUID` 改名)已經發生過一次,而改漏其中一份不會紅燈——那條路徑
會安靜地一條規則都比對不中,症狀是面板降級成泛用句、歷史少了摘要與數值,
都還是「有東西顯示」。

## 做法

新增 `src/sources/panelRules.ts`,把走訪與比對收成單一出處:

- `boundToPanel(annotations, dashboardUid, panelId)` — **全專案唯一**比對那兩個註解鍵的地方;
  鍵名本身提成 `DASHBOARD_UID_ANNOTATION` / `PANEL_ID_ANNOTATION` 兩個常數,Grafana 再改名時只動這裡。
- `panelRulesOf<T>(raw, uid, panelId)` — Prometheus rules 端點形狀(`{ data: { groups } }`)。
- `panelRulerRulesOf<T>(raw, uid, panelId)` — ruler API 形狀(`{ <資料夾>: [group] }`)。
  兩支只差外層攤平,內層(`groups → rules → 比對`)是共用的。

回傳 generator 而非陣列:三個 parser 的輸出型別各不相同(一個陣列、兩個 Map),
中間不必先長出一份用完即丟的清單。每次 yield `{ rule, annotations }`——`annotations`
取好且保證存在(缺就是 `{}`),因為 `parseRulesResponse` 需要它當 instance 註解的 fallback
(`a.annotations ?? ann`),呼叫端不必再 `?? {}` 一次。

型別參數 `T` 由呼叫端指定:回應沒有型別保證,「這條規則有哪些欄位」的宣告留在真的去讀那些
欄位的地方(`panelAlerts.ts` 的 `FiringRule`、`history.ts` 裡兩個區域型別),共用模組不替
三個用途猜一份聯集。

三個 parser 因此各自縮成「取欄位」:`parseRulesResponse` 47 → 19 行(另把它讀的欄位抽成
檔內的 `FiringRule` 宣告)、`parseRuleTemplates` 29 → 18 行、`parseRulerConditions` 28 → 13 行。

### AC-1 的量尺:為什麼限定在 `src/sources/`

票上留言(非 collaborator,僅供參考)指出的(a)成立,實查屬實:`src/module.ts:10-14` 的註解
裡有「alert rule 需帶 `__dashboardUid__`/`__panelId__` 註解」這句話,那是在說 dashboard 側的
前提,**不是比對程式碼**。全 `src` 的 grep 因此會列出 `module.ts` 而「只剩 1 個檔」假性失敗。

本票範圍寫明「只動 `src/sources/`」,所以不去動 `module.ts` 的註解;改以 `src/sources/` 為
量尺範圍,結果是 1 個檔(見上)。留言的(b)也採納了——兩個標籤一起釘,`panelId` 的比對同樣
只剩 `panelRules.ts` 一處。

同一個理由下,`panelAlerts.ts` 內**降級路徑的那行註解**原本也寫了這兩個字面標籤,
已改寫成「規則沒帶綁定本 panel 的註解,見 panelRules.ts」——它在本票範圍內,且留著會讓
`src/sources/` 的量尺也假性失敗。語意未變。

留言最後那句疑慮(「本副本沒有 history.ts」)不成立:本分支的 `src/sources/history.ts` 存在,
`parseRuleTemplates` 與 `parseRulerConditions` 都在,三份合一的前提成立。
