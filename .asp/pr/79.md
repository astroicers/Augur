# refactor(feed): 清單列的合併、篩選與空清單判斷抽成純函式 buildFeedRows

Closes #79

## 問題

`src/components/MascotPanel.tsx` 的 `renderFeedLines` 在 render 裡同時做四件事：
合併 sessionOnly 列（以 `SESSION_MATCH_WINDOW_MS` 比對句子**與時間**）、套篩選字串、
決定空清單提示、產 JSX。前三件沒有自己的單元測試，只能靠 render 整個面板間接驗；
而後續的紀錄匯出、清單標記兩張票都要讀「現在畫面上的那幾列」。

## 做法

新增 `src/feed/feedRows.ts`，把前三件搬進去；元件只剩「把結果映射成 JSX」。
**對外行為不變**（AC-4 的既有斷言一行未改且全綠）。

| 匯出 | 做什麼 |
| --- | --- |
| `buildFeedRows(feed, history, filter, formatWhen?)` | 回傳 `{ rows, emptyText }` —— 要顯示的列，與空清單時的提示文字 |
| `FeedRow` | 畫面上的一列：`{ key, origin: 'session' \| 'history', when, text }` |
| `FeedRowsResult` | `{ rows: FeedRow[]; emptyText: string \| null }`；`rows.length === 0` 與 `emptyText !== null` 恆等價（有一支測試釘住） |
| `FeedLine` | 本分頁念過的一句。型別從 `MascotPanel.tsx` 搬過來，元件改成 import |
| `SESSION_MATCH_WINDOW_MS` | 合併窗（10 分鐘）。常數與原註解整段搬過來，值未改 |
| `FEED_EMPTY_TEXT` | 三種空清單提示的具名常數（`session`／`history`／`filtered`），字串逐字照舊 |
| `formatHistoryWhen(time, now?)` | 原 `MascotPanel.tsx` 的私有 `formatWhen`，多收一個 `now` |

元件那一側剩下：

```tsx
const { rows, emptyText } = buildFeedRows(feed, history, historyFilter);
if (emptyText !== null) {
  return <span className={styles.empty}>{emptyText}</span>;
}
return rows.map((r) => (
  <div key={r.key} className={styles.line} data-origin={r.origin}>…</div>
));
```

### 時鐘：合併與篩選不需要時鐘，顯示字串才需要（回應票上留言 (a)）

合併規則比的是**兩個既有時間戳**——紀錄的 `entry.time` 與念出時刻 `line.at`
（`Math.abs(e.time - l.at) <= SESSION_MATCH_WINDOW_MS`），**沒有「現在」**。
所以 `buildFeedRows` 的三個決策面（合併、篩選、空清單）是輸入的純函式，
不必注入時鐘，測試也不用控時間。

唯一讀時鐘的是**顯示字串**：`formatHistoryWhen` 要分辨「今天」才決定顯不顯示日期
（抽出前是 `MascotPanel.tsx` 裡直接 `new Date()` 的私有函式）。兩道處理：

1. `formatHistoryWhen(time, now = Date.now())` —— 「現在」變成參數，那個判斷在測試裡可控；
2. `buildFeedRows` 的第四個參數可注入整個 formatter，預設就是 `formatHistoryWhen`。
   測試一律注入一個樣板字串 formatter（`t` → `@<t>`），所以列與時間戳的對應驗得出來，而且不看 locale 臉色
   （`toLocaleTimeString` 的輸出隨環境而變，拿它當期望值的測試在別台機器上會紅）。

因此 AC-1 的簽名維持票文寫的 `buildFeedRows(feed, history, filter)`：第四個參數選填，
呼叫端（元件）不傳。

### `search` 欄不進 `FeedRow`

篩選用的 `search`（句子＋所有 label 值、已轉小寫）是合併過程的中間產物，
留在函式內部的區域型別裡，不往外露。對外的 `FeedRow` 就是「畫面上看得到的那四個欄位」，
後續兩張票要的也是這個。

### 沒有紀錄時篩選字串不生效 —— 照舊

抽出前 `!history` 那條路徑整段不碰 `historyFilter`（篩選框本來就只在紀錄模式顯示），
抽出後同樣：`history === null` 時直接把 `feed` 映射成列，`filter` 不讀。這點有測試釘住，
免得日後有人「順手補上」而改了行為。

留言 1（`asp-ng-supervisor-legacy[bot]`，**非** repo collaborator）依 §10 只供參考、

- **(a)「要嘛注入時鐘，要嘛明說只比對兩個既有時間戳、不需要時鐘」**：查過之後是**後者**

  新模組，並讓「現在」與整個 formatter 都可注入（見上方〈時鐘〉），測試因此不看時鐘、
  也不看 locale 臉色。這比留言的任一選項都嚴一點，但方向一致。
