# docs: 過期事實收尾（散落-2、asset 殘句與壞表格、speakableSeverity 措辭、一條測試名稱）

Closes #61

## 問題

四處各自獨立的小帳，半徑都在文件（加一條測試的**名稱**），不碰產品碼：

1. **散落-2**：「`src/core` 273 行、零修改」的說法早已不成立。#31（commit「docs: ARCHITECTURE、README、src/README、CHANGELOG 與程式現況對齊」）已經把寫死的行數清掉，但留下的更正句本身寫成「**不是「零修改」**」——字串還在，`grep "零修改"` 照樣命中，AC-1 要求的是零命中。
2. **asset**：`docs/asset-provenance.md`〈A1 出處調查〉末段仍寫「待專案主人回想服務」「在確認之前：A1 維持現狀（已在版控中）」，與同一份文件上面的〈A1 已退出版控（2026-09-21）〉直接矛盾。
3. **壞表格**：同檔〈進版控的資產〉表的分隔列與第一筆資料列之間多一行空行，Markdown 因此在分隔列就結束表格，nami 與 logo.svg 兩列（以及 sprite 那一列）被當成段落渲染。
4. **措辭**：`docs/ARCHITECTURE.md` 說 `speakableSeverity`「只正規化大小寫」。實際上 `src/core/format.ts` 的它還會去掉前後空白，並把缺值／空白／非字串收斂成 `unknown`。
5. **測試名稱**：`format.test.ts` 的「髒嚴重度不改變句型——子句數與乾淨輸入相同」，名稱說的（句型不變）比斷言驗的（只比子句數）大。#46 對同型的 name 測試已改成「名稱子句不被省略」，這條比照。

## 做法

### AC-1 散落-2

改寫 `README.md`〈這個 repo 的其他目錄〉的 `src/core/` 列，與 `docs/ARCHITECTURE.md`〈關鍵設計〉那段括號。兩處都不再出現「零修改」與寫死的行數；引用改用 commit 訊息標題（AC-1 指定的作法）：

- `fix(sources): 泛用 episode 被取代後，降級路徑會永久靜音`（加 `forget()`）
- `fix(panel): 會讓面板永久靜音的三條路徑，以及 speaker.ts 的第一份測試`（加 `setWindow()`）

### AC-2 asset

- 殘句：在那兩段前面加一個引用塊的時效標記，寫明「**以下兩段 2026-09-21 已被退出版控取代**」，並說清楚取代的事實（服務想不起來 → 沒有「回想並確認」這條路 → 直接走了段落自己寫的 remedy；角色已於 2026-10-05 重新設計）。原文逐字保留，當作當時的判斷紀錄。段後補一句界定取代範圍：被取代的只有 A1 的處置，**對新素材**「產生當下就記錄出處」那條規則不受影響、仍然有效——那條規則混在同一段裡，整段打叉會連它一起廢掉。
- 壞表格：刪掉分隔列後的那一行空行。

### AC-3 措辭

`docs/ARCHITECTURE.md` 那句改成「去掉前後空白、轉小寫，缺值、空白與非字串一律收斂成 `unknown`」，並指向 `src/core/format.ts`。逐字核對過實作：`speakableSeverity` 以 `severity.ts` 的 `normalize`（trim + toLowerCase + 非字串回 `null`）取值，`null` 或空字串回 `'unknown'`。

### AC-4 測試名稱

只改那一條的 `test(...)` 名稱字串，斷言與其他測試一行未動（見 `git diff`：該檔只有 1 行變更）。

## 判讀說明

- **AC-1 的「過期的 tools 列」查無可改**：票文列的位置包含 `docs/ARCHITECTURE.md` 的 tools 列，但 #31 已經把它改成「`asp-test.sh`（11 道本地檢查電池）與它呼叫的守門腳本、`sprite-gen/`、`tts-server/`。逐項說明見 `README.md`〈這個 repo 的其他目錄〉」。實查 `tools/asp-test.sh`，會進 `FAILED` 的檢查有 typecheck、lint、js-suffix、monitoring、grafana-version、bundle-deps、sprites、sprite-selftest、stroke-battery、tts-server 共 10 道，加上 jest（含 `MIN_TESTS` 下限）正好 11 道，`tools/` 底下的腳本也與敘述相符。**沒有過期的事實可改，故該列未動**；若要的其實是別的過期點，請指出字串。
- **AC-1 的 ARCHITECTURE「兩處零修改」同樣只剩一處**：票上留言（非 collaborator，僅供參考）提到的 `:59`、`:75`、`:79` 三處命中是 #31 合併前的快照；本分支 base 上只剩〈關鍵設計〉那一處，README 則剩「不是「零修改」」那一句。兩處都已改掉，AC-1 的 grep 判準達成。
- **asset 殘句用「標記 + 保留原文」而不是刪除**：AC-2 的字面要求是「標『2026-09-21 已被退出版控取代』」，不是刪段；且該段落尾句夾著一條**仍然有效**的新素材規則，整段刪掉會一併廢掉它。因此採保留原文加時效標記，並明寫取代範圍。
- **AC-4 的名稱未逐字照抄票上的示例**：示例是「嚴重度子句不被省略——子句數與乾淨輸入相同」，本檔同一群測試都以「髒嚴重度」開頭（`髒嚴重度一律念 unknown`、`髒嚴重度不拋例外`…），故寫成「髒嚴重度時嚴重度子句不被省略——子句數與乾淨輸入相同」以維持前綴一致。語意與示例相同：只描述斷言驗得到的事。
