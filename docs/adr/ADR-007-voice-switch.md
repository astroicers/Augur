## 痛點 / 需求

v0.2.0 以前，panel 上那顆鈕叫「啟用語音」。它做的事只有一件：在使用者手勢裡叫醒語音引擎（`Speaker.unlock()`）。

- **它看起來像開關，按下去卻沒有任何可見變化**，按完還是「啟用語音」。
- **沒有辦法閉嘴。** 值班室、開會中、或單純不想聽的人，只能把整個 panel 的語音選項關掉 —— 那是 dashboard 層的設定，會動到所有看這個 dashboard 的人。靜音其實是「我這台瀏覽器」的偏好，不是 dashboard 的設定。
- **被瀏覽器擋下的播報就永遠消失了。** 瀏覽器的 autoplay 政策規定使用者在頁面上互動過之前不准發聲（`SpeechSynthesisErrorEvent.error === 'not-allowed'`；外部語音則是 `AudioContext` 起不來）。開頁面時已經在燒的告警因此一句都沒念出來，事後點了「啟用語音」也不會補。

## 決策

### 1. 靜音是「每個瀏覽器各自」的設定，持久化在 localStorage

「啟用語音」鈕換成語音開關：`🔊 語音開` / `🔇 靜音中`（被擋時第三態 `🔊 點一下啟用語音`，見決策 2）。

- **狀態存在 `localStorage`**，鍵為 `augur-mascot-panel.muted`（值 `'1'` / `'0'`）。重新整理後仍然記得。
- **同一頁多個吉祥物 panel** 以自訂事件 `augur-mascot-panel:muted`（`CustomEvent<boolean>`）在同一個 click 事件裡同步派送；**跨分頁**靠瀏覽器原生的 `storage` 事件。
- 靜音只停語音：**表情、精靈圖、播報紀錄（ADR-006）照常運作**，告警照樣進清單，只是不念。
- 切到靜音時停掉正在念與排隊中的句子、停掉嘴型驅動並把嘴型歸零；切回開時叫醒引擎。同頁同步是在同一個 click 事件裡同步派送，所以**仍算使用者手勢**，被同步叫醒的那個 panel 的 `unlock()` 不會被 autoplay 政策擋掉。
- `localStorage` 讀寫一律包 `try/catch`：無痕模式或使用者清掉網站資料時讀寫會丟例外，**失敗就當作沒靜音、只在這次分頁內記得**，不讓開關整個壞掉。

**為什麼**：靜音是「看的人」的偏好，不是「dashboard 怎麼設定」的偏好。同一面牆上的兩個人，一個要聽一個不要，panel 選項給不了這個。而 `localStorage` 正好是 per-origin、per-browser 的，語意和需求對得上。

**被否決的替代**：

| 替代 | 為什麼不 |
|---|---|
| 存在伺服器端（使用者偏好 API 或自建後端） | **違反 ADR-004 零後端**。ADR-004 決策 1 明文「不自建任何後端」，ADR-006 也為了同一條規則把紀錄做成唯讀。為了一個布林值開後端，代價與收益完全不成比例 |
| 做成 panel 選項（存進 dashboard JSON） | 那會變成**所有觀看者共用**的設定，而且要有 dashboard 編輯權限才改得動。Viewer 帳號（kiosk、值班）根本改不了，等於沒有開關 |
| 存進 dashboard 的 URL 變數 | 重新整理會留著，但換一條連結、或從別處點進來就沒了；也會污染分享出去的網址，把「我這台靜音」傳染給收到連結的人 |
| 只存在 React state（不持久化） | 重新整理就恢復成會念。牆面螢幕與長時間開著的分頁最常遇到的就是重新整理 |
| `sessionStorage` | 不跨分頁、關掉分頁就沒了。靜音偏好的壽命應該比一個分頁長 |
| 用 `localStorage` 的 polling 代替事件同步 | 同頁同步要即時（按下去另一個 panel 要立刻跟上），polling 做不到「在同一個 click 事件裡同步」，被同步的 panel 的 `unlock()` 就不在使用者手勢裡，會被 autoplay 政策擋掉 |

### 2. 被瀏覽器擋下的句子，10 分鐘內按一下可以補念

被 autoplay 政策擋下的句子記在一份清單裡。按下按鈕時（這一下就是使用者手勢）叫醒引擎，並把**最近 10 分鐘內**被擋的句子重新排進佇列。

- 這一下的語意是**「叫醒」而不是「切成靜音」**：按完狀態維持「語音開」。否則使用者會按一下、發現變成靜音、再按一下才會念，而且第一下被擋的內容已經丟了。
- 外部語音（ADR-005）被 autoplay 政策擋下時**不會丟錯誤**，而是降級並把原因寫進聲線標籤（`autoplay-blocked`）。這種情形同樣算「被擋」，按鈕同樣顯示「點一下啟用語音」。
- **「試聽」被擋下不補念** —— 那只是測試聲音，不是告警。判定用的是 `WeakSet` 的**物件身分**而不是名字：一條真的叫 `preview` 的告警不該因此永遠不補念。
- 清單在**寫入時**就修剪（丟掉超時的、見決策 3 的去重），不是只在讀取時才篩。沒人點的牆面螢幕配上重播間隔時，清單才不會無限長。

**為什麼是 10 分鐘**：牆面螢幕可能好幾小時沒有人碰。第一次有人走過去點一下，不該讓吉祥物開始補念幾十句早就過時的話 —— 那既吵又沒有資訊價值。10 分鐘是「還算現在的事」與「已經是歷史」之間的一條線；真正要翻舊帳的人有播報紀錄（ADR-006）可以看，而且紀錄是完整的、不受這個窗限制。

**被否決的替代**：

| 替代 | 為什麼不 |
|---|---|
| 全部補念，不設時限 | 牆面螢幕放一整夜，早上有人點一下 → 吉祥物連念幾十句過時告警，要幾分鐘才念得完，期間新的告警排在後面 |
| 完全不補念（只叫醒引擎，被擋的就算了） | 這正是 v0.2.0 的行為，也是這條決策要修的痛點：開頁面時已經在燒的告警一句都聽不到 |
| 只補念最後一句 | 被擋期間同時燒起來的多條不同告警，只聽到一條，而且不知道漏了什麼 |
| 自動偵測第一次互動（`click` / `keydown` 掛在 document 上）自動補念 | 使用者只是想捲動 dashboard，吉祥物突然開始講話。發聲應該是**明確要求**的結果，不是副作用 |
| 綁 dashboard 的 refresh 間隔而不是固定 10 分鐘 | 間隔可以設成 5 秒或 1 天，用它當時限會得到兩種都不合理的極端 |

### 3. 同一則告警只補念最後狀態

補念時，同一個告警名稱（`BroadcastPlan.name`）只念最新的那一則。被擋期間「偵測到 → 已恢復」的告警，補念時只念恢復句。

**為什麼**：補念的目的是讓人知道**現在是什麼狀況**，不是重播一段錄音。被擋期間翻了三次的告警，念三次「偵測到…已恢復…偵測到」只會讓人更困惑，而最後那一句才是現況。完整的時序要查的話，播報紀錄（ADR-006）有每一次狀態變化，而且那份紀錄讀的是 Grafana 自己存的歷史，比瀏覽器記得的更完整。

去重做在**寫入**與**讀取**兩處：寫入時同名的舊項目就被換掉，按下時再依名字取最後一筆。兩道的理由不同 —— 寫入時那道是為了讓清單不長大，讀取時那道是正確性。

**被否決的替代**：

| 替代 | 為什麼不 |
|---|---|
| 逐句補念，保留完整時序 | 翻轉中的告警會念出自相矛盾的一串；要時序去看紀錄（ADR-006）比用聽的準確得多 |
| 只念「還在燒」的，恢復句丟掉 | 「我開頁面前它恢復了」也是使用者要知道的事，而且恢復句是最常見的最後狀態 |
| 把被擋的句子合併成一句摘要（「期間有 3 則告警」） | 要另外寫一套組句，與 `src/core/` 的既有組句分岔 —— ADR-006 決策 3 已經為同一個理由否決過「紀錄與播報各寫一套」 |
| 依 fingerprint 而非告警名稱去重 | 播報端的 dedup（`src/core/dedup.ts`）本來就只看規則名（ADR-004 實作）。補念用更細的鍵，會和「同一則告警只念一次」的既有語意分岔 |

## 接受的代價

- **換一台電腦、換一個瀏覽器、換一個 profile，靜音偏好就不跟著走。** 這是 per-browser 的直接後果，也正是決策 1 要的語意，但使用者在多台機器之間移動時要各設一次。
- **無痕模式與「清除網站資料」會讓偏好消失**，而且 `localStorage` 被完全封鎖時連這次分頁以外都記不住。降級行為是「當作沒靜音」—— 選擇會念而不是不會念，因為「靜音靜默生效」比「忘記靜音」更難診斷。
- **被擋清單只活在記憶體裡。** 重新整理就沒了，所以「開頁面 → 被擋 → 重新整理 → 按一下」補不回重新整理前被擋的句子。要查那段時間發生什麼事，靠播報紀錄（ADR-006）。
- **10 分鐘是拍板的數字，沒有量測支撐。** 不是從使用者行為資料推出來的，而是「還算現在」的直覺。真的不合用時改這個常數即可，沒有其他東西依賴它。
- **`storage` 事件在某些瀏覽器的同一分頁內不觸發**（規格就是這樣：只通知其他分頁），所以同頁同步必須另外用 `MUTE_EVENT`，兩套機制並存。
- **同一則告警只補念最後狀態，意味著補念出來的句數可能少於被擋的句數**，使用者不會知道中間略過了幾句。紀錄（ADR-006）有完整的每一次變化。

## 不採用的選項

| 選項 | 為什麼不 |
|---|---|
| 保留「啟用語音」鈕，另外加一顆「靜音」鈕 | 兩顆鈕的狀態組合（已啟用 × 已靜音）要使用者自己在腦中推演；而且「啟用語音」在已經解鎖之後就是一顆永遠沒反應的鈕 —— 那正是要修的毛病 |
| 用瀏覽器的分頁靜音（使用者自己在分頁上按靜音） | 那會連 dashboard 上其他東西的聲音一起靜掉，而且 panel 不知道自己被靜音了，佇列照跑、嘴型照動，畫面會說謊 |
| 把 `speechSynthesis.volume` 設成 0 | 句子照樣「念完」，佇列照樣被佔用，重播間隔照樣消耗 —— 看起來靜音，資源沒省，而且外部語音（ADR-005）走的是 Web Audio，不吃這個設定 |
| 靜音時連播報紀錄一起停掉 | 靜音是「不要出聲」，不是「不要知道」。紀錄是唯讀的視覺資訊，沒有理由跟著消失 |

## Follow-up / POC gate（升 `Accepted` 前必過）

- **G-ADR007-1 真瀏覽器的靜音持久化**：真 Grafana 上按下靜音、重新整理，仍然是靜音；`localStorage` 裡確實是 `augur-mascot-panel.muted=1`。
- **G-ADR007-2 跨分頁同步**：同一個瀏覽器開兩個分頁，一邊按靜音，另一邊在不重新整理的情況下跟上（驗的是真的 `storage` 事件，不是 jsdom 的假事件）。
- **G-ADR007-3 真 autoplay 被擋 → 補念**：在**沒有互動過**的真瀏覽器分頁上讓一條告警燒起來（確認真的出現 `not-allowed`），按一下按鈕，聽到補念且狀態維持「語音開」。jsdom 測不到真的 autoplay 政策。
- **G-ADR007-4 10 分鐘窗**：被擋超過 10 分鐘的句子在真環境確實不補念（可暫時調小常數驗，但要以正式值跑一次）。
- **G-ADR007-5 外部語音路徑**：填了 `ttsEndpoint` 時，被 autoplay 政策擋下的外部語音按一下能叫醒（`AudioContext` 真的 resume），聲線標籤回到「外部語音」。
- **G-ADR007-6 無痕 / 封鎖 localStorage**：無痕模式或封鎖網站資料時，開關仍可用、預設為「語音開」、本分頁內切換有效。

## 待驗風險

1. **`speechSynthesis` 的 `not-allowed` 不是所有瀏覽器都丟。** 實作只認這一個錯誤碼；某些瀏覽器可能靜默不發聲而不回報錯誤，那樣就沒有東西寫進被擋清單，按鈕也不會顯示第三態。目前只在開發環境的 Chromium 系列驗過。
2. **外部語音被擋的判定靠聲線標籤裡的 `autoplay-blocked` 字串**（`remoteSpeaker` 寫入）。那是兩個模組之間的字串約定，不是型別，改了一邊不會有編譯錯誤。
3. **Grafana Frontend Sandbox 開啟時 `localStorage` 是否照常可用未驗。** ADR-005 待驗風險也列了 sandbox 下的未驗項；sandbox 若改寫 storage 存取，靜音偏好可能靜默退化成「只在這次分頁內」。
4. **同一頁很多個吉祥物 panel 時，`MUTE_EVENT` 會對每一個派送。** 目前試用 dashboard 最多兩個，數量級大上去的行為沒量過。
5. **重播間隔（`repeatFiringMin`）與補念窗的交互。** 持續燒的告警在被擋期間會重複進被擋清單，寫入時的去重擋掉了成長，但「補念的是最後一次重播的句子」這個行為沒有專門的真環境驗收。
